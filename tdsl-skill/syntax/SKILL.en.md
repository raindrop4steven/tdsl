# TDSL Syntax (Complete Reference)

> [中文](SKILL.md) · **English**

> Core: **the surface syntax uses TS lexical forms** (`function/const/for-of`), while **skeleton declarations use domain keywords** (`entity/page/interface`).
> This is not strict TypeScript: `@pk` and `Order.where(...)` don't exist in TS; the built-in types are domain types (`Integer/Decimal` — there is **no** `number/string`).
> **Forbidden list** (most commonly written by mistake): ternary `?:`, template strings, `==` (always `===`), arrow functions, `class`, `:=`, `for-in`, `logic`. Legacy lexical forms have been removed — using them raises a syntax error.

## 0. One-minute example

```
@datasource('defaultDS')

entity Todo {
  id: Integer @pk;
  title: String;
  done: Boolean;
}

@export
function listTodos(): List<Todo> {
  return Todo.all;
}

interface TodoApi {
  GET '/api/todos' -> listTodos
}

page TodoList {
  <table dataSource={useQuery('listTodos')}>
    <column field="title" />
  </table>
  <button text="New" action={navigate('TodoCreate')} />
}
```

## 1. Top-level declarations

### dependency (declare dependencies; third-party libraries must be declared before use)

```
dependency java "g:a:v" import { JSON, JSONObject };      // import list: classes usable by bare name
dependency java "com.fasterxml:jackson:2.17.0" as jackson; // as ns = namespace, call via jackson.JSON
dependency npm "antd@^5.21.0";                             // pure dependency, only enters package.json
dependency npm "echarts-for-react" import ECharts;         // default-exported component
dependency npm "@ant-design/charts" import { Pie, Bar };   // named exports (one package, multiple components)
```

- Java coordinates → pom.xml; npm → package.json. **Using without declaring = D-dep-1 error**.
- A `java` declaration needs the corresponding scanned artifact under the project's `libs/*.json` (generated by `tdsl bundle-jar <jar> -o libs/x.json`).
- `as ns` disambiguates same-named classes; reference via `ns.JSON.toJSONString(...)`.

### @datasource (data source / namespace scope)

```
@datasource('erp')
entity Order { ... }

@datasource('crm')
entity Order { ... }          // same-named entities across data sources can coexist
```

- A standalone top-level statement; subsequent entities belong to the current source until the next switch.
- Reference by short name; **cross-source ambiguity must use a qualified name** `erp.Order` / `crm.Order` (omitting it raises an error).

### entity

```
entity Order {
  id: Integer @pk;
  title: String;
  total: Decimal @nullable;
  status: OrderStatus;        // enum type referenced directly
  supplierId: Integer @ref(Supplier);               // FK: shows reference name + dropdown
  areaId: Integer @nullable @ref(AreaDict, display: 'name');
  parentId: Integer @nullable @ref(ProductCategory); // self-reference still needs explicit @ref
  createdAt: DateTime;
}
```

Property annotations: `@pk` (primary key; basis of `Entity.get(id)`), `@nullable`, `@unique`, `@ref(entity[, display:'field'])`.
Built-in scalars: `Integer Decimal String Boolean Date Time DateTime` (no number/string/Date).

**Foreign-key rule (compiler infers nothing)**: only an explicit `@ref` renders a reference dropdown/name; a field merely named `xxxId` doesn't count.
`display` defaults to `'name'`; a missing field raises `FK-REF-DISPLAY`; the target entity needs a `query*` returning `List<that entity>` as the dropdown source (missing → `FK-REF-NO-QUERY` warning).

### struct / enum

```
struct OrderInput {
  title: String;
  items: List<OrderItemInput>;      // nested List structure
}

enum OrderStatus { DRAFT, SUBMITTED }
enum DocStatus { DRAFT('Draft'), SUBMITTED('Submitted') }          // KEY('label') display label
enum AuditStatus { DRAFT('Draft', 'orange'), PASS('Pass', 'green') }  // label color declared by the business
```

Color whitelist: `green/red/orange/blue/purple/cyan/magenta/gold/default` or `#hex`.

### service (external system integration: dubbo/http)

```
@service(kind = 'dubbo', group = 'user-center', version = '1.0.0')
service UserSvc {
  getUser(id: Integer): User;
}

@service(kind = 'http', baseUrl = 'http://erp-center')
service ErpApi {
  GET '/api/orders/{id}' -> getOrder(id: Integer): Order;    // http must carry METHOD + path
}
```

Inside a `function` it's called like a local method: `userSvc.getUser(id)`. Generates `@DubboReference` / `@FeignClient`.
**Local jar classes do not use `service`** — declare them with `dependency java` + a libs artifact, then call directly from a function.

## 2. Business logic function (the TS lexical surface)

```
@export
function createOrder(input: OrderInput): Order {
  if (input.items.count === 0) { return null; }
  const order = new Order();
  order.total = 0;
  order.save();
  for (const it of input.items) {
    it.save();
  }
  return order;
}
```

| Form | Semantics |
|---|---|
| `const x = expr` / `const x: T = expr` | Variable declaration (the only form) |
| `if (cond) {...} else {...}` | Condition; **no ternary** |
| `for (const x of xs)` | Iterate a List (the only form) |
| `throw 'Only draft orders can be submitted';` | Business exception → HTTP 400, frontend shows an error toast |
| `===` / `!==` | Equality (**no ==**) |
| `&&` `\|\|` `!` | Logical |
| `+ - * /` | Arithmetic (Decimal auto-wrapped as BigDecimal) |

### Entity methods

```
Order.get(id)                 // static: lookup by primary key
Order.all                     // static: whole table (start of ForEach/query chain)
entity.save() / entity.delete()   // instance: persist (write ops are auto-transactional)
```

### Query language

```
Order.where(total > 0)                              // condition: = >= <= > < like in (= means "equals"!)
Order.where(billNo like '%x%', status = status)     // comma = AND; && / || allowed inside conditions
Order.where(...).orderBy(total desc)                // sort (direction asc|desc)
Order.where(...).limit(10)                          // limit rows → findTop10
Order.where(...).page(1, 20)                        // pagination → Page<T>
Order.aggregate(sum(total))                         // aggregate: sum/avg/max/min/count
Order.aggregate(sum(total)).groupBy(customer)       // group by → List<Map<Object>>
```

### List / string methods (FFI kernel)

```
xs.add(x)   xs.count   xs.get(i)   xs.contains(x)   xs.isEmpty
s.trim()  s.toUpperCase()  s.toLowerCase()  s.contains(x)  s.startsWith(x)  s.endsWith(x)
s.replace(a, b)  s.substring(i, j)  s.indexOf(x)  s.isEmpty  s.length
```

### @ok (operation feedback text)

```
@export
@ok('Claimed')
function takeCustomer(id: Integer): Boolean { ... }
```

A button calling `useMutation('takeCustomer', row.id)` shows "Claimed" on success; without it the default is "Success". **Business copy lives in TDSL** — the generator only transports it.

## 3. interface (REST contract)

```
interface OrderApi {
  GET '/api/orders' -> listOrders
  GET '/api/orders/{id}' -> getOrderDetail     // {id} path parameter
  POST '/api/orders' -> createOrder
}
```

**Functions referenced by page bindings must be exposed by an interface endpoint**, otherwise typecheck fails (a battle-tested rule that prevents a blank frontend).

## 3.5 Auth & session (M11)

```
@auth(user: 'SystemUser', username: 'username', password: 'password',
      loginPage: 'Login', registerPage: 'Register')
```

- **The single app-wide auth switch** (all five fields required; nothing inferred): an app without `@auth` generates no auth layer at all;
- Login/registration are **ordinary functions + interface** (endpoints under `/api/auth/**` are auto-allowed, all other `/api/**` return 401); passwords use the platform primitives `Auth.hash(raw, salt)` / `Auth.matches(raw, stored, salt)` (backend-only);
- **Token issuance/validation and the frontend session (localStorage + authFetch + route guards + top-bar user + logout) are all managed by the generator — TDSL has no concept of a token** — the login function just returns a struct containing token/userId, and the wrapper fills in the token;
- Page annotation `@public` = no login required and excluded from the main layout/menu (for login/register pages); password input `<input field="password" type="password" />`;
- On a successful form submit, login/register pages redirect automatically (login → home, register → login page).

## 4. page / dialog

```
@title('Sales Bill List')
@menu('Sales')                     // top-bar module + left menu group ('module/group' allows two levels)
page SalesBillList {
  <input field="billNo" label="Bill No" />       // search-condition area
  <table dataSource={useQuery('searchSalesBills')}>
    <column field="status" title="Status" />          // enum column auto-colored tag
    <button text="Edit" action={openDialog('SalesBillEdit', row)}
            disabled={row.status === DocStatus.AUDITED} />   // disabled once audited
    <button text="Approve" action={useMutation('auditSalesBill', row.id)}
            visible={row.status === DocStatus.UNAUDIT} />    // mutually exclusive by status
    <button text="Unapprove" action={useMutation('deauditSalesBill', row.id)}
            visible={row.status === DocStatus.AUDITED} />
  </table>
  <button text="New Sales Bill" action={openDialog('SalesBillEdit')} />
}

@title('Edit Sales Bill')
dialog SalesBillEdit {
  <form submit={useMutation('saveSalesBill')}>
    <input field="billNo" label="Bill No" />
    <repeat field="items">
      <input field="qty" label="Qty" />
      <input field="price" label="Unit Price" />
    </repeat>
    <summary field="items" expr={qty * price} label="Total Amount" />  // line-total sum (live)
    <summary field="items" of="qty" label="Total Qty" />               // single-field sum
    <button text="Save" />
  </form>
}

@title('Sales Bill Detail')
dialog SalesBillDetail {
  <detail dataSource={useQuery('getSalesBillDetail', initial.id)}> // drawer detail: single row by selection
    <text field="bill.billNo" title="Bill No" />
    <repeat field="items" title="Line Items">                            // read-only child table in detail
      <column field="goodsId" title="Product" />
      <column field="qty" title="Qty" />
    </repeat>
  </detail>
  <button text="Edit" action={openDialog('SalesBillEdit', row.bill)} />
}
```

### Bindings (the only data channel)

| Binding | Semantics |
|---|---|
| `useQuery('fnName')` | Fetch data → hook state feeds the component |
| `useMutation('fnName', args...)` | Submit → auto-refetch on success |
| `navigate('PageName', row.id)` | Page navigation |
| `openDialog('DialogName', row)` | Open drawer |

Parameter references: `$route.id` route param / `row` table row / `initial.id` (selected row id inside a drawer).

### Built-in components

```
table column button form input repeat text detail summary
tag(color) statistic(title,value) tabs > pane(title)
checkbox switch radio(options="A,B") avatar badge(count) card(title)
```

Form type auto-upgrade: enum → Select / date → DatePicker / number → InputNumber.

### Action availability & shape (enterprise patterns)

- `visible={cond}`: when unsatisfied, **not rendered** (mutually exclusive actions such as approve/unapprove).
- `disabled={cond}`: when satisfied, **grayed out** (placeholder kept).
- A `text` containing "Delete"-like text triggers an auto Popconfirm.
- Page-level buttons go to the action area at the right of the title; more than 3 collapse into "More".
- The condition expression is a subset of row context: `row.<field>` comparisons + `EnumType.MEMBER` + `&& / || / !`.

### Expression domain (G2)

```
<input field="amount" derive={qty * price} />        // derive: pure function → computed readOnly
<input field="goodsId" carryBy="getGoods">           // carry: fill in after selection
  <input field="goodsName" />
</input>
```

IO bindings (useQuery/useMutation) are forbidden inside `derive`; the function referenced by `carryBy` must return an entity containing all child fields.

### Line-item carry (edit a list directly with line items)

```
<repeat field="items" dataSource={useQuery('queryErpPurchaseOrderItems', initial.id)}>
  <input field="productId" label="Product" />
  ...
</repeat>
```

Priority: query-result items ?? initial.items ?? empty row; in create mode no request is sent (guard).

## 5. Third-party library integration (full flow)

```
① scan   tdsl bundle-jar D:/x.jar -o <project>/libs/x.json [--classes JSON,JSONObject]
② declare  dependency java "g:a:v";          (npm likewise: dependency npm "pkg" import { Pie };)
③ use   call JSON.toJSONString(o) directly inside a function; use <Pie /> directly in a page; imports are auto-generated
```

Same-named classes colliding on alias (fastjson/jackson both ship `JSON`) → D-dep-4 error; resolve either by changing the artifact alias or by `as ns` qualification → `ns.JSON`.

## 6. Multi-file projects (sharding convention)

- The directory is the app; the global namespace is shared across files — **entity/enum/function/page names are globally unique**.
- Split shards vertically by functional domain: `00-model` (enums + entities + structs) → `10-xx` (each business domain: logic + pages) → portal last.
- Each shard may contain only what it uses; same-named entities across sources are separated by `@datasource`.
- See the 8-shard organization in `../demo-yudao/tdsl/`.
