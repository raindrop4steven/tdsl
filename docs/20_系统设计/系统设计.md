## 1. 顶层架构（分层）

```
  用户自然语言需求
        │  (LLM, 见 §7)
        ▼
 ┌──────────────────────────┐
 │   TDSL 书写投影（书写面）    │  ◀── LLM 主入口（TS 风格，近乎本能），tsc 可辅助校验
 └───────────┬──────────────┘
             │  Parser 编译
             ▼
 ┌──────────────────────────┐
 │   Typed AST（语义核）       │  ◀── 唯一事实来源（SSoT），类型化、可分析、可检查
 └───────────┬──────────────┘
             │  serialize / deserialize（可选）
             ▼
        JSON AST（存储/流通/LLM 中间产物，派生视图）
             │
             │  codegen 编译到目标
             ▼
    ┌────────────────┐   ┌────────────────┐
    │  React 前端      │   │  Java 后端      │
    │ (组件/API/hooks) │   │ (Entity/Service)│
    └────────────────┘   └────────────────┘
```

**分层职责（对比 NASL）：**
- TDSL 书写投影 = 输入面（给 LLM/人）——替代 NASL 仅作展示的 Natural TS，转为主书写面。
- Typed AST = 语义核/事实来源——替代 NASL 作为事实来源的 JSON AST。
- JSON AST = 派生的序列化视图——不是源。
- 编辑器 UI 元信息 = 独立分层，不进入语义核。

## 2. 模块划分（monorepo package）

```
packages/
  core/          # Typed AST：节点判别联合、TypeRef、App 模型、TreeNode 对象模型、resolve/nodePathOf
  parser/        # TDSL(TS投影) → AST；json <-> ast 互转
  schema/        # zod 校验 schema、JSON AST 序列化/反序列化
  typecheck/     # 完整类型检查器：绑定/类型推导/兼容性/隐式转换/泛型统一/诊断
  codegen-react/ # 前端生成器（React + hooks + axios）
  codegen-java/  # 后端生成器（Spring Boot + JPA）
  llm/           # prompt pack、TDSL/JSON 直出、LLM 输出的校验修复管线
  cli/           # dsl parse | generate | check | build
  playground/    # TDSL / JSON / AST 互转试验台
```

依赖方向（从低到高）：
`core` <- `parser`/`schema`/`typecheck` <- `codegen-*` <- `llm`/`cli`/`playground`

## 3. 核心域概念（数据模型）

| 领域 | 概念 | 说明 |
|------|------|------|
| 应用 | `App` | 语义树根；聚合所有领域 |
| 数据源 | `DataSource`, `DataSourceConfig` | 数据库/外部数据源 |
| 实体 | `Entity`, `EntityProperty`, `EntityIndex`, `Enum`, `EnumItem` | 后端持久化模型 |
| 结构 | `Structure`, `StructureProperty`, `TypeParam` | DTO/嵌套结构 |
| 逻辑 | `Logic`, `Param`, `Return`, `Statement`, `Expr` | 后端业务方法（含小语言） |
| 接口 | `Interface`, `Endpoint`, `HttpMethod` | REST 契约 |
| 页面 | `View`, `ViewElement`, `Page`, `Binding` | 前端页面/组件/数据绑定 |
| 流程 | `Process`, `ProcessNode`, `ApprovalPolicy` | 审批/工作流（P1 视业务裁剪） |

每个域概念都实现 `BaseNode`：`kind`(类型标签) + `id` + 语义性 `annotations?`。

## 4. 引用与寻址

- 跨节点引用（实体、结构、逻辑、页面元素）以 **nodePath 字符串** 保存。
- 编译期 `resolve(app, path)` 解析为真实对象并绑定校验；解析失败报错。
- 提供 `nodePathOf(node)` 编码、`resolve(app, path)` 解码。
- 表达式中调用/取属性即通过存引用 path 实现。

nodePath 形态（参考 NASL 命名空间，简化）：`app.datasources.defaultDS.entities.Product`

## 5. 代码生成子系统

```ts
type Target = 'react' | 'java';
interface GeneratedFile { path: string; content: string; }

interface CodeGenerator<T extends Target> {
  generate(app: AppNode): GeneratedFile[];
}

class JavaGenerator  implements CodeGenerator<'java'>  {} // Entity(JPA) / Logic(Service) / Interface(Controller)
class ReactGenerator implements CodeGenerator<'react'> {} // View(Component) / Interface+Logic(axios+hooks)
```

- 生成器内部对节点做 **穷尽 switch + never 收窄**。
- 平台差异翻译层：`===`/`Boolean&&` → Java `equals`/`and`；集合/日期/精度处理映射。
- 每个领域独立 Generator（Entity/Logic/Interface/View），串成统一入口。

## 6. 数据流

```
TDSL文本 ──parse──▶ Typed AST ──typecheck──▶ OK ──codegen──▶ React/Java 文件
   │                    │
   │                    ├──serialize──▶ JSON AST ──(存储/LLM回流)
   │                    └──<──deserialize
   └──(也可)─────────── LLM 直出 JSON AST ──zod 校验──▶ Typed AST
```

## 7. LLM 集成管线

双通道，收敛到同一 Typed AST：
- **路径 A（推荐）**：LLM 直出 TDSL（TS 书写面）→ parser → AST。TS 风格少幻觉，tsc 可辅助校验。
- **路径 B**：LLM 直出 JSON AST → zod 校验/修复 → AST。无 parser 的快速通道。

prompt pack 内容：返回 JSON 的 schema、概念清单、TS 书写面语法、命名空间规则、通用模板。

```
自然语言 → [LLM] → TDSL/JSON → [parse|zod] → Typed AST → [typecheck] → [codegen] → React/Java
```

## 8. 部署架构（运行期平台模式，对齐网易 CodeWave）

> 定位确认：TDSL 平台是**运行期在线生成**（用户自然语言 → LLM → 编译器 → 生成并部署微服务），
> 编译器为**常驻服务**，而非仅构建期 CLI。

```
用户自然语言
   │  (LLM 管线，§7)
   ▼
Node 编译器微服务（编译服务，独立 Docker 部署）
   │  parse → typecheck → codegen（纯函数、确定性，与 CLI 共用同一套 packages/*）
   ▼
生成完整工程（React/Java 源码）→ CI/CD 流水线 → 新微服务上线（Nacos/Feign/K8s 常规生态）
```

与 Java 微服务生态的结合方式（异构微服务）：
- **编译服务**：Node 包成独立微服务，注册 Nacos、暴露 REST API（`/compile`、`/validate`）、健康检查、独立部署与监控。Java 侧通过 Feign/HTTP 调用，与调其他 Java 服务无差别。
- **运行时不依赖**：编译器只出现在"代码生成"环节；生成的 Java 微服务在运行时与编译器完全解耦。
- **双形态复用**：同一套编译器代码既是 CI 构建期工具（开发期调试），又是常驻编译服务（运行期平台）——纯函数/确定性保证两者输出一致。

工程要求（P2）：
- 编译服务 API 契约：`validate(TDSL|JSON) → { ok, diagnostics }`、`compile(TDSL|JSON, target) → GeneratedFile[]`。
- 生成产物与部署流水线对接：完整工程（含 pom.xml/package.json 脚手架）直接交给 CI/CD。
- `node:crypto` 等 Node 特定依赖收敛，保证编译器核心可在任意 JS 运行时（含浏览器 playground）复用。

## 9. 非功能设计
- **纯函数/确定性**：codegen 输出确定性，利于 diff 与回归。
- **类型安全**：判别联合 + never 穷尽；zod 运行时校验。
- **可测试**：AST 到文本/JSON 互转可做往返（round-trip）测试；生成器可做快照测试。
- **可观测**：parse/typecheck/codegen 错误带 nodePath 和行号。
