# 00 总览：流水线与核心哲学

> 配套代码：`examples/todo-app/scripts/slice.ts`（闭环驱动入口，66 行读它就懂数据流）

## 1. 整条流水线

```
todo.tdsl ──parse──▶ Typed AST ──typecheck──▶ { ok, diagnostics }
   （文本）    @tdsl/parser      @tdsl/core      @tdsl/typecheck
                                               │ ok
                               ┌───────────────┴───────────────┐
                               ▼                               ▼
                     @tdsl/codegen-java                 @tdsl/codegen-react
                     Spring Boot 工程                     Vite + React 工程
                     mvn compile ✓                       vite build ✓
```

包依赖方向（从底到顶）：`core` ← `parser` / `typecheck` ← `codegen-java` / `codegen-react`。

外围还有一圈**工具链与外壳**（不进编译主干，见 `06_工具链与外壳`）：

| 包 | 干什么 |
|----|--------|
| `cli` | `dsl parse/check/generate/build/bundle-jar` 命令行 |
| `llm` | Prompt Pack：示例矩阵 / prompt 组装 / 诊断回流修复 |
| `playground` | 浏览器试验台（Monaco + 实时诊断/AST/双端代码） |
| `server` | 在线 TDSL Agent（聊天 + 编译裁判 + 沙箱 + 运行回路） |
| `eval` | LLM 生成质量评测基线（样卷 + harness） |

## 2. 三种角色

| 角色 | 包 | 干什么 |
|------|-----|--------|
| **进**（文本 → 可信 AST） | `core` / `parser` / `typecheck` | 把 LLM/人写的 TDSL 炼成干净、类型化、检查过的语义树 |
| **出**（AST → 可编译产物） | `codegen-java` / `codegen-react` | 把同一棵 AST 翻译成双端工程，语义一致 |
| **外壳**（用编译器的人/机接口） | `cli` / `llm` / `playground` / `server` / `eval` | 复用编译管线，不新增语义 |

## 3. 四个咬合各包的约定

1. **判别联合 + `never` 穷尽** —— 每个节点用 `kind` 字段做类型标签，TS 靠它收窄；生成器 switch 完所有 kind 后放 `const _never: never = x`。以后新增节点类型但没更新生成器，TS 编译直接报错——**这是设计而非负担**。
2. **nodePath 字符串引用** —— 跨节点引用（如 `List<Todo>` 里的 `Todo`）不存对象指针，存字符串路径 `app.datasources.defaultDS.entities.Todo`，编译期 `resolve()` 绑定，悬空引用被编译器捕获。
3. **纯函数 / 确定性输出** —— codegen 返回 `GeneratedFile[]`（path + content）不碰磁盘；同 AST 必得同输出，可快照测试、可 diff 回归（M7 多文件对拍就靠它）。
4. **诊断可编程寻址** —— `Diagnostic{path, line?, col?, file?, message, severity}`，`path` 是 nodePath 不是文本；M7 后还带 `file`。LLM 修复管线、编辑器高亮、spec 对拍全靠它。

## 4. 两个关键产品类型

```ts
interface GeneratedFile { path: string; content: string; }   // codegen 统一产出

interface Diagnostic {
  path: string;        // 出错节点 nodePath（可编程寻址，不是文本报错）
  line?: number;
  col?: number;
  file?: string;       // M7 多文件工程：诊断归属的分片
  message: string;
  severity: 'error' | 'warning';
}
```

## 5. 当前能力盘点（2026-09，261 单测实测）

| 里程碑 | 一句话 |
|--------|--------|
| P0~P2 | 五包闭环 / CRUD / 复杂逻辑（运算符、@Transactional、Decimal 算术） |
| M1 | 命名空间：实体短名归数据源作用域、限定名 `ds.Entity`、歧义报错 |
| M2 | 查询语言：where 复合条件、orderBy/page/limit、aggregate+groupBy |
| M4 | View 声明层：`page` + JSX 子集 → antd 真生成、多页面路由 |
| M6 | 外部能力：`service`（dubbo/bean/http）+ `component`（npm 组件） |
| M7 | 多文件工程：`parseProject` 分片合并、诊断带 file、对拍单文件 |
| M8 | CLI：五命令薄命令层（可测可复用） |
| M9/M10 | 在线 Agent：pi SDK 会话、compile_tdsl 裁判、run_app 运行回路 |
| P11 | 双语法：`logic↔function`、`:=↔const(: T)`、`for-in↔for-of`（AST 同构零改动） |

| dev/32 | 依赖声明：`dependency java/npm` 进 AST + 扫描产物外置 libs/ + alias 唯一不变式 |
