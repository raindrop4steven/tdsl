## 1. 目标与核心路线

**用大模型生成低代码系统**。核心思路参考网易 CodeWave 的 NASL（见 `00_参考资料/`），
但摆脱其面向编辑器的 JSON AST，从编译器/LLM 视角重新设计：

> **LLM 写 TDSL（书写面）→ parser 炼 Typed AST（语义核/SSoT）→ typecheck 校验 → 生成 React + Java**

三个消费端都顺：
1. **给 LLM 写** → TS 风格，训练语料多、近乎本能、少幻觉；
2. **给编译器炼** → 类型化 AST，合格的中间表示；
3. **给用户/产物** → 同一棵 AST 分别生成 React 与 Java，语义一致。

**非目标（第一版不做）**：不让 LLM 直接写业务代码（失去语义控制力）；不做在线可视化编辑器 UI（预留元信息分层）；不做应用编排/发布流水线。

**验收标准**：① 自然语言需求 → 端到端产出可编译的 React + Java 工程；② LLM 产物能被 parse + 校验 + 编译，错误可定位；③ 语义可复用（同一 AST 双端一致）；④ 新增节点时编译器强制穷尽处理。

## 2. 关键决策（D1-D7）

| # | 决策 | 内容与理由 |
|---|------|-----------|
| D1 | **Typed AST 是唯一事实来源（SSoT）** | NASL 把 JSON AST 当事实来源（编辑器视角）；我们用类型化对象树，JSON 只是派生视图。JSON 序列化/zod 校验明确范围外——未来接编辑器时按需补 |
| D2 | **判别联合 + `never` 穷尽** | 节点用 `kind` 字面量做标签，不用运行时字符串；新增节点未处理时 TS 编译报错（设计而非负担） |
| D3 | **nodePath 字符串引用 + 编译期 resolve** | 跨节点引用存 `app.datasources.erp.entities.Order` 形态的路径，`resolve()` 绑定校验，悬空引用报诊断；改名不靠全文改串 |
| D4 | **书写层 = TS 风格 + 领域扩展（⚠️ 非严格 TS 子集，口径修正 2026-09）** | "自研"指 AST/语义是自己的；书写层大量借用 TS 手感（表达式/控制流）。领域扩展：entity/struct/logic/page/service/component、@pk 注解、where/orderBy 查询 DSL、`Decimal(10,2)`。两处有意偏离：`:=` 声明（避免与 `=` 混淆）、`for-in`（遍历元素，语义同 for-of）。**实测 tsc 无法直查**（`:=`/for-in 解析失败），语法校验以自家 parser 为权威；LLM 收益来自风格相似性，不依赖严格子集性 |
| D5 | **TDSL 是 LLM 主输入面** | 借鉴 NASL Natural TS 但转为主要书写面；parser（带行列错误定位）编译为 AST 并做权威校验 |
| D6 | **编辑器 UI 元信息独立分层** | 语义核只放语义性注解；布局/label 等不进语义核 |
| D7 | **类型系统走"较重：完整类型检查器"**（演进中） | 目标：类型推导、子类型/隐式转换（Integer→Decimal）、泛型实例化与统一、诊断带 nodePath/行列。当前实现为"最小绑定 + 确定场景校验 + 宽松放行"（M3 加深，设计见 dev/11） |

## 3. 分层架构与模块

```
  用户自然语言需求
        │  (LLM 管线，§7)
        ▼
 ┌──────────────────────────┐
 │   TDSL 书写投影（书写面）    │  ◀── LLM 主入口（TS 风格 + 领域扩展），自家 parser 为权威校验
 └───────────┬──────────────┘
             │  Parser 编译
             ▼
 ┌──────────────────────────┐
 │   Typed AST（语义核）       │  ◀── 唯一事实来源（SSoT）
 └───────────┬──────────────┘
             │  codegen 编译到目标
             ▼
    ┌────────────────┐   ┌────────────────┐
    │  React 前端      │   │  Java 后端      │
    │ (组件/API/hooks) │   │ (Entity/Service)│
    └────────────────┘   └────────────────┘
```

| 包 | 职责 |
|----|------|
| `core` | 语义核：节点判别联合、TypeRef、符号表（M1 分层作用域）、nodePath 寻址（零运行时依赖） |
| `parser` | TDSL 文本 → AST（词法 + 递归下降 + linkApp 短名绑定），错误带行列 |
| `typecheck` | 诊断：悬空引用、实体方法/查询链、View 绑定、外部能力（M3 加深） |
| `codegen-java` | App → 完整 Spring Boot 工程（JPA/Repository QuerySpec/Service/Controller/Feign） |
| `codegen-react` | App → 完整 Vite+React 工程（api/hooks/pages/router，antd 组件映射） |
| `llm` | Prompt Pack：示例矩阵、五层 prompt 组装、诊断回流修复闭环 |
| （规划）`cli` / `playground` | dsl parse/generate/check/build；TDSL/JSON/AST 互转试验台 |

依赖方向：`core` ← `parser`/`typecheck` ← `codegen-*` / `llm` ← 应用层。

## 4. 核心域概念与引用寻址

| 领域 | 概念 | 说明 |
|------|------|------|
| 应用 | `App` | 语义树根，聚合 datasources/structures/enums/logics/interfaces/views/services/components |
| 数据源 | `DataSource` | 实体的作用域（M1：实体短名归数据源，跨源同名合法，`dsName.Entity` 限定引用） |
| 实体 | `Entity`/`EntityProperty` | 后端持久化模型（`@pk @nullable @unique`） |
| 结构 | `Structure`/`StructureProperty` | DTO/嵌套结构（支持 `List<struct>`） |
| 逻辑 | `Logic`/`Param`/`Return` | 后端业务方法，body 为小语言语句序列 |
| 接口 | `Interface`/`Endpoint` | REST 契约（GET/POST/PUT/DELETE `'/path' -> logic`），绑定到 Logic |
| 页面 | `View`/`ViewElement`/`Binding` | `page` 声明（JSX 子集），useQuery/useMutation/navigate 绑定 |
| 外部能力 | `Service`（dubbo/bean/http）/`Component` | 调三方后端、引 npm 组件，主航道一等公民 |

每个节点实现 `BaseNode { kind, id, annotations? }`。
跨节点引用以 **nodePath 字符串** 保存，编译期 `resolve(app, path)` 解析校验（悬空报诊断）；
类型引用短名解析规则：优先当前数据源作用域 → 全局 → 跨源歧义则要求限定名（M1）。

## 5. 语义核类型速览（SSoT：`packages/core/src/types.ts`）

```ts
TypeRef = primitive(7 内置) | reference(nodePath) | generic(List|Map|Page) | db(decimal(p,s))

Expr   = Ident | Member | Index | Call | New | NewList | Literal(Bool|Numeric|String|Null)
       | Binary(=== !== && || + - * / < <= > >= = like in) | Group
Statement = VarDecl(:=) | Assign | Return | If | ForEach(in) | While | Break | Continue | CallStmt | Block
```

- 书写面 → AST 归一：`@pk` → `primary`；`Decimal(10,2)` → `db` TypeRef；`:=` → `VarDecl`；
  `new List<T>()` → `NewList`；`for (x in y)` → `ForEach`；`useQuery('logic')` → `Binding`。
- 查询 DSL：`X.where(...)`（条件 `field op value`，逗号=AND，`&&/||` 组合）、
  `.orderBy(f asc|desc)`、`.page(n,size)`、`.limit(n)`、`.aggregate(sum/avg/max/min/count)`、`.groupBy(f)`。
- 内置类型层级（typecheck 用）：`Any` 为顶、`Null` 为底；隐式转换 `Integer → Decimal` 单向。

> 本文档只保留速览；完整判别联合以 `packages/core/src/types.ts` 为准（改类型时看它，别看文档）。

## 6. 代码生成

| 目标 | 生成 |
|------|------|
| Java（Spring Boot + JPA） | Entity→JPA 实体（类型映射 `Integer→Long`、`Decimal→BigDecimal`、`DateTime→ZonedDateTime`）；Logic→Service 方法（写操作自动 `@Transactional`）；Interface→`@RestController`；查询→Repository **QuerySpec 机制**（去重后每形态一个方法：派生名 `findByXxxOrderByYyyDesc` / `findTopN` / `Pageable` / JPQL 聚合）；service(dubbo/bean/http)→接口 + `@DubboReference`/`@Autowired`/`@FeignClient` |
| React（Vite + antd） | Interface→fetch 封装（api.ts）；page→组件（pages/）+ react-router 路由表；Binding→自研 `useQuery`/`useMutation` hooks；ViewElement→antd 组件映射（table→Table、detail→Descriptions、三方 component→import npm 包）；`$route.id`→动态路由参数 |

- 生成器内部对节点做**穷尽 switch + never 收窄**；平台差异（`===`→`equals` 等）在生成器翻译层做。
- **纯函数/确定性**：返回 `GeneratedFile[]` 不碰磁盘，同 AST 必同输出（可快照 diff 回归）。

## 7. LLM 管线与 Prompt Pack（dev/19 已实现组装层）

```
自然语言 → [LLM + PromptPack] → TDSL → [parse] → Typed AST → [typecheck] → [codegen] → React/Java
                                       ▲                        │
                                       └──── 诊断回流修复闭环（≤N 轮）──┘
```

- **Prompt Pack 五层**：角色 → 语法速查（~400 token 围栏）→ 示例矩阵（5 领域可编译样例，单测锁定永不腐烂）→ 需求 → 输出契约。
- **示例主导**（研究共识：小众语言能力主要来自 few-shot 示例，显式规则只做约束围栏）。
- **修复闭环**：parse 错误带行列、typecheck 诊断带 nodePath（人话化），要求 LLM 输出完整修正稿。
- 路径 B（LLM 直出 JSON AST + zod）为备选，未实现。

## 8. 部署形态（运行期平台模式，P2 规划）

```
用户自然语言 → [LLM 管线] → Node 编译器微服务（parse→typecheck→codegen，纯函数确定性）
             → 生成完整工程（React/Java 源码）→ CI/CD → 新微服务上线（Nacos/Feign/K8s 常规生态）
```

- 编译服务：Node 包独立微服务，注册 Nacos、暴露 `/compile`、`/validate`；Java 侧 Feign/HTTP 调用无差别。
- 运行时不依赖：编译器只在"代码生成"环节出现，生成的服务与它完全解耦。
- 双形态复用：同一套代码既是 CI 构建期工具，又是常驻编译服务。

## 9. 非功能约定

- TS strict；**禁止** `as any` / `@ts-ignore`；判别联合 + never 穷尽。
- codegen 纯函数/确定性；错误带 nodePath + 行列。
- 可测试：单测（vitest）覆盖 parser/typecheck/codegen；示例矩阵锁定可编译性；E2E 用 `npm run slice`（todo.tdsl → 双端真实 build）。
