# 第 10 章 React 代码生成：从 AST 到前端工程

`generateReact(app)` 把同一棵 AppNode 翻译成 Vite+React 工程。这一章展示代码生成的另一个维度：从**声明式 View 子树**生成**命令式 React 组件树**。

## 10.1 生成物全景

一个 TDSL 应用生成的 React 工程：

```
package.json / vite.config.ts / .npmrc     # 脚手架
index.html / src/main.tsx
src/api.ts                                  # 每个 endpoint → 一个 fetch 函数
src/hooks.ts                                # useQuery/useMutation 真实实现
src/pages/OrderList.tsx                     # 每个 page → 一个组件
src/pages/OrderCreate.tsx
src/App.tsx                                 # react-router 路由表
src/pages/SalesBillEdit.tsx (dialog)        # dialog 组件（不进路由）
```

与 codegen-java 的核心区别：React 生成器**不做类型映射**（JS 是动态类型），而是做**组件映射**——TDSL 的声明式元素（`<table>`、`<form>`、`<input>`）被翻译成 React + antd 的组件树。

## 10.2 从 Binding 到 hooks

第 5 章讲了 Binding 如何在 parser 中提取。codegen-react 收集每个页面的 query/mutation/navigate 绑定，生成 hooks 调用：

```tsx
export default function OrderList() {
  const q = useQuery(() => listOrders(), []);
  // q.data → 表格数据源

  return (
    <Table
      columns={[
        { title: 'id', dataIndex: 'id' },
        { title: 'customer', dataIndex: 'customer' },
        // ...
        { title: '操作', render: (_, row) => (
          <>
            <Button onClick={() => navigate(`/orders/${row.id}`)}>详情</Button>
            <Button onClick={() => del(row.id)}>删除</Button>
          </>
        )}
      ]}
      dataSource={q.data}
    />
  );
}
```

**mutation 后自动 refetch**：当一个页面既有 `useQuery('listOrders')` 又有 `useMutation('deleteOrder', row.id)` 时，生成的代码在 mutation 成功后自动重新调用 query：

```tsx
const q = useQuery(() => listOrders(), []);
const del = useMutation(
  (id) => deleteOrder(id),
  { onSuccess: () => q.refetch() }      // 自动 refetch
);
```

这是"声明式绑定"的回报：生成器知道 `deleteOrder` 会改变列表数据，所以自动把 mutation 完成后关联到 query——不需要用户显式写刷新逻辑。

## 10.3 ViewElement → antd 映射

`ANTD_OF` 表是 ViewElement 类型 → antd 组件的映射：

| TDSL 元素 | 生成 | 说明 |
|-----------|------|------|
| `<table dataSource={...}>` | `<Table columns=...>` | column.field 数据驱动列 |
| `<form submit={useMutation(...)}>` | 受控表单 + 提交按钮 | form 包住子控件 |
| `<input field=...>` | `<Input>` / 类型升级控件 | 字段 useState 提升 |
| `<repeat field="items">` | `.map()` 循环 | 嵌套明细行编辑 |
| `<text field="order.customer" />` | `<span>{data.order.customer}</span>` | 点路径渲染 |
| `<detail dataSource={...}>` | `<Descriptions>` | 详情展示 |
| `<button text=... action=...>` | `<Button onClick=...>` | 操作按钮 |
| dialog | 弹窗组件 + openDialog | import 相对路径 |

**表单控件按字段类型升级**：`<input field="status" />` 如果 `status` 在实体中是枚举类型，生成的控件是 `<Select>`（选项来自 TDSL enum），日期字段生成 `<DatePicker>`，数字字段生成 `<InputNumber>`。这是跨层信息流通的典型——视图层用 typecheck/codegen 从 AST 反查实体字段类型，决定组件形态。

## 10.4 页面组件生成：usesState 提升

`<input field="customer" />` 没有显式的 `value=...`——那它的状态放哪？

TDSL 的约定是：**表单字段的状态自动提升到组件顶部**：

```tsx
export default function OrderCreate() {
  const [customer, setCustomer] = useState('');
  const [items, setItems] = useState([{ product: '', price: 0, qty: 0 }]);
  // 提交
  const submit = useMutation((p) => createOrder(p), { onSuccess: ... });

  const handleSubmit = () => {
    submit({ customer, items });
  };

  return (
    <Form onFinish={handleSubmit}>
      <Form.Item label="customer">
        <Input value={customer} onChange={(e) => setCustomer(e.target.value)} />
      </Form.Item>
      {items.map((it, i) => (
        <div key={i}>
          <Input value={it.product} onChange={(e) => setItems(updateItem(i, 'product', e.target.value))} />
          {/* ... */}
        </div>
      ))}
      <Button htmlType="submit">提交</Button>
    </Form>
  );
}
```

生成器遍历 ViewElement 树，收集所有 `<input field=...>` 字段，生成对应的 useState 和受控组件。字段名 `customer` → 变量名 `customer` + setter `setCustomer`——命名约定与字段名紧密绑定，保证生成代码的一致性。

## 10.5 嵌套结构与 repeat

`<repeat field="items">` 用于主子表明细编辑。生成器反查 structure 类型（AST 中的 `OrderInput.items: List<OrderItemInput>`）获得子项结构，然后生成 `.map()` 渲染：

```tsx
{items.map((it, i) => (
  <div key={i}>
    <Input value={it.price} onChange={(e) => setItems(updateItem(i, 'price', Number(e.target.value)))} />
    ...
  </div>
))}
```

`repeatItemStruct` 反查是"声明驱动生成"的另一个例子——`<repeat field="items">` 本身不携带结构信息，生成器从 AST 的类型声明中推导。

## 10.6 路由生成与 `$route`

页面 → URL 的映射规则：

```tsx
function routePathOf(viewName: string): string {
  // OrderList → /orders（kebab-case）
  return '/' + viewName
    .replace(/([a-z0-9])([A-Z])/g, '$1-$2')
    .toLowerCase();
}
```

`OrderList` → `/orders`，`OrderCreate` → `/orders-create`（set 不会被拆分，因为前面是数字）。

**动态路由参数**：`navigate('OrderDetail', row.id)` 和 `useQuery('getOrderDetail', $route.id)` 一起工作：

```
OrderDetail → /orders/:id
```

生成的代码：

```tsx
export default function OrderDetail() {
  const { id } = useParams();                     // react-router 的动态参数
  const q = useQuery(() => getOrderDetail(Number(id)), [id]);
  // $route.id → Number(params.id)
}
```

`$route.id` 是 TDSL 的**虚拟变量**——它表示"当前路由的动态参数"。codegen 把包含 `$route.id` 的表达式翻译为 `Number(params.id)`，其中 `params` 来自 `useParams()`。

## 10.7 Interface → api.ts

每个 endpoint 生成一个 fetch 函数：

```ts
export async function listOrders(): Promise<Order[]> {
  const res = await fetch('/api/orders');
  if (!res.ok) throw new Error(await res.text());
  return res.json();
}

export async function getOrderDetail(id: number): Promise<OrderDetail> {
  const res = await fetch(`/api/orders/${id}`);
  if (!res.ok) throw new Error(await res.text());
  return res.json();
}

export async function createOrder(input): Promise<Order> {
  const res = await fetch('/api/orders', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(input),
  });
  if (!res.ok) throw new Error(await res.text());
  return res.json();
}
```

规则：
- GET + 路径参数 → 模板字符串 `\`/api/orders/${id}\``
- GET + 标量参数 → URL query 拼装
- POST/PUT + 结构 → `JSON.stringify(input)` + body

## 10.8 依赖合并：默认依赖 + dependency npm

`package.json` 的 dependencies 两路合并：

1. 页面骨架默认项：`antd`、`dayjs`、`react-router-dom`、`react`、`react-dom`
2. `dependency npm` 声明：**唯一的三方包名来源**（dev/33 删除了 component 注册层）

```json
{
  "dependencies": {
    "antd": "^5.21.0",
    "dayjs": "^1.11.0",
    "react": "^18.2.0",
    "react-dom": "^18.2.0",
    "react-router-dom": "^6.22.0",
    "echarts-for-react": "^3.0.2"
  }
}
```

三方组件的 import 语句也由声明生成：

- `dependency npm "echarts-for-react" import ECharts;` → `import ECharts from 'echarts-for-react'`
- `dependency npm "@ant-design/charts" import { Pie, Bar };` → `import { Pie, Bar } from '@ant-design/charts'`

页面可以直接写 `<ECharts dataSource={...} />`——生成的组件文件会自动带正确的 import。

## 10.9 前端语义的隔离

一个贯穿 codegen-react 的设计原则：**前端概念不在 AST 中**。

AST 的 View 子树只包含声明式描述——`<table>`、`<input>`、`useQuery` 绑定。React 特有的东西（useState、useEffect、hooks、antd 组件、路由）全部在 codegen-react 层合成。

这个隔离的价值：

1. **AST 保持跨端中立**：同一棵 AST 既能生成后端 Service（codegen-java），也能生成前端 hooks（codegen-react）。如果 AST 混入 React 概念，Java 生成器会被污染。

2. **语义在 AST，实现细节在 codegen**：`<table dataSource={useQuery('listOrders')}>` 的语义是"页面有一张表格，数据来自 listOrders 函数"。React 如何实现（`useState` 存储数据、`useEffect` 拉取、`Table` 组件渲染）是前端细节，属于 codegen-react 的翻译选择。

3. **前端 UI 特定信息通过 props 传递**：`@title('销货单列表')`、`<column field="billNo" title="销货单号" />` 这些会传给 `ViewElementNode.props`，由 codegen-react 消费。语义核只保存它们，不解释它们。

## 10.10 前端生成的特殊挑战

与 Java 生成器相比，React 生成有几个独特挑战：

**状态管理**：React 组件有状态（useState），而 TDSL 的 page 声明没有显式状态。生成器需要从 ViewElement 树推断状态变量（哪些字段需要 useState）。这是"声明式 → 命令式"翻译的典型挑战。

**组件树的组装**：JSX 的嵌套需要正确的闭合标签和 Fragment。一个 `<repeat>` 会生成 `items.map(...)` 且需要 `key` 属性。生成器必须保证生成的 JSX 在语法上是合法的。

**hooks 的规则**：React 要求 hooks 在组件顶层调用，不能放在条件/循环里。生成器必须保证所有 `useQuery`/`useMutation`/`useState` 的调用出现在组件函数的顶层。这是生成器受限的设计决策带来的——因为绑定的位置由 TDSL 的 View 结构决定，而不是由用户自由书写。

**长尾 bug 治理**：白屏级 bug（import 路径错误、Fragment 缺失、重复声明）是 React 代码生成的高发区。TDSL 的策略是对拍单测锁定——每修一个白屏 bug 就补一条单测，防止回归。
