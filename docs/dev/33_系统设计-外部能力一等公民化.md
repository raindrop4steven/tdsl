# dev/33 系统设计 — 外部能力一等公民化（bean/component 删除）

> 切面：外部依赖与三方能力的书写面简化。
> 背景（用户批评）：对外宣称"java/npm 一等公民、直接用"，但 bean 要 `@service(kind='bean', jar='g:a:v')` 手写坐标+签名、component 要注册 pkg——依赖写两遍、多一层封装，与一等公民承诺矛盾。
> 状态：已交付（2026-09-13）

## 1. 决策

| 语法 | 处置 | 理由 |
|------|------|------|
| `service kind='bean'` | **删除** | 本地 jar 类与 FFI 直调（dev/27+32）完全重叠：`dependency java` 声明坐标 + libs 产物提供签名 + function 直调。bean 的 jar 字段/手写操作/生成 interface 是重复的第二通道 |
| `component` 语法 | **删除** | npm 一等公民对标 java 侧：页面直接写三方组件标签，import 包名由 `dependency npm` 声明解析——包名不写两遍，无注册层。B3 d.ts 投影是完整形态（props/events 类型校验），当前宽松透传 |
| `service kind='dubbo'` | **保留，重定位** | 引用别人家**运行中的** RPC 服务（注册中心 group/version 是运行时配置）——不是依赖封装，是分布式架构声明 |
| `service kind='http'` | **保留，重定位** | 声明别人家 REST API 契约（baseUrl/method/path）——同上 |

**边界口径**：`dependency` 管"我的工程要用什么库"（编译期）；`service dubbo/http` 管"我的工程调谁家的远程服务"（运行时）。bean 混淆了两者，删。

## 2. 改动清单

- parser：删 bean kind（service 仅 dubbo|http）；删 component 顶层语法与 `ComponentNode` 产出
- core：删 `ComponentNode`（never 穷尽强制收窄所有消费端）
- typecheck：删 component pkg 校验；三方组件元素改由"页面用到的组件名 → dependency npm 匹配"校验（无声明报 D-dep 口径）
- codegen-react：三方组件 import = 组件名 → 在 `app.dependencies(eco=npm)` 中匹配包名（匹配规则：包名最后一段/去 scope 后与组件名 camel 化比对；未命中报诊断且 import 跳过）；package.json 依赖只来自 `dependency npm`
- codegen-java：删 bean 的 pom 注入与 interface 生成分支
- llm 示例矩阵 external-service 重写（dubbo/http + dependency npm 直用组件）
- 手册/cheatsheet/教程同步

## 3. 验收标准

1. `service kind='bean'` 解析报错（kind 白名单仅 dubbo|http）
2. `component` 顶层声明报语法错误；页面 `<ECharts .../>` 解析通过、import 由 dependency npm 匹配
3. 页面用了未声明 npm 依赖的组件 → 诊断带"补 dependency npm"口径
4. 全量回归：test/typecheck/slice/slice:multi/check-spec 全绿
