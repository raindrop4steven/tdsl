## 1. 语法面（core/parser/typecheck 落点）

### 1.1 core：`AppNode.auth?` 侧车

```ts
// types.ts 新增（侧车字段，非 nodes 判别联合成员 → 不触发全仓 switch 爆炸）
export interface AuthConfigNode extends BaseNode {
  kind: 'Auth';
  /** 用户实体 nodePath（app.datasources.x.entities.SystemUser） */
  userPath: string;
  usernameProp: string;   // 'username'
  passwordProp: string;   // 'password'
  loginPage: string;      // 'Login'（公开页名，显式声明）
  registerPage: string;   // 'Register'
}
// AppNode: auth?: AuthConfigNode
```

### 1.2 parser 文法

```
顶层    @auth ( user : 'SystemUser' , username : 'username' , ... )   // 复用 parseServiceConfig KV 形态
页面    @public                                                       // 无参注解 → pendingViewAnnos 无值标记
input   <input field="password" type="password" />                    // 属性解析已支持 string，零改动透传
```

- 顶层注解分派新增 `ann === 'auth'` 分支：`parseServiceConfig()` → 组装 `AuthConfigNode` 挂 `app.auth`（后写覆盖前写，单值）；
- `user: 'SystemUser'` 短名在 `linkApp` 阶段绑定为 nodePath（同实体引用短名解析规则：当前数据源 → 全局，歧义报错）；
- `@public`：页面注解分派（`title/menu/role` 同位）新增无参形态，存 `view.annotations`（`{name:'public'}`）。

### 1.3 typecheck：AUTH-\* 诊断

| 码 | 级别 | 触发 | message 要点 |
|----|------|------|--------------|
| AUTH-USER | error | `auth.userPath` resolve 失败 | `@auth 用户实体 'X' 不存在` |
| AUTH-FIELD | error | username/password 缺失或非 String | `@auth 字段 'password' 必须是实体 X 的 String 字段` |
| AUTH-PAGE | error | loginPage/registerPage 页面不存在 / 未标 @public | `@auth 登录页 'Login' 未找到或未标 @public` |
| AUTH-UNIQUE | warning | username 无 @unique | `建议为 @auth 用户名字段加 @unique` |

- 校验时机：`check(app)` 主流程实体/视图遍历后追加 `checkAuth(app)`（独立小节，非侵入）；
- **缺 `app.auth` 时本节整体跳过**（零新诊断，A10 前提）。

## 2. codegen-java 落点（仅 `app.auth` 存在时）

### 2.1 生成文件清单（`authFiles(pkg, app)`，插入 `generateJava` 尾部）

| 文件 | 内容要点 |
|------|----------|
| `entity/AuthToken.java` | `@Entity @Table(name="auth_token")`：`id @GeneratedValue(IDENTITY)` / `token(UNIQUE, VARCHAR(64))` / `userId(BIGINT)` / `expiresAt(TIMESTAMP)`；`@Enumerated` 不涉及 |
| `repository/AuthTokenRepository.java` | `Optional<AuthToken> findByToken(String token);` + `deleteByExpiresAtBefore(LocalDateTime)` |
| `support/PasswordUtil.java` | `static String hash(String raw, String salt)` / `static boolean matches(...)`：`MessageDigest SHA-256(raw + ':' + salt)` → Base64 |
| `support/AuthInterceptor.java` | `preHandle`：`/error` 或白名单 → true；取 `Authorization: Bearer x` → `authTokenRepository.findByToken` → 过期/缺失 `response.setStatus(401)` 写 `{"message":"未登录或登录已过期"}` 返回 false；命中 → `request.setAttribute("currentUser", userId)` |
| `support/WebMvcConfig.java` | `@Configuration implements WebMvcConfigurer`：`addInterceptors` 注册，`excludePathPatterns("/healthz", "/api/auth/**", "/error")` |
| Controller 注入 | `login` 端点所在 Controller 方法**不改动**——签发下沉到 Service |

### 2.2 Service 注入（login function 生成处）

- 判定：`app.auth` 存在 && 该 logic 是 `loginPage` 表单 submit 绑定的函数 && 返回类型为 struct `LoginResult`（名字以 `auth.loginPage` 对应页面 submit 链推导，不猜）——**简化口径**：返回类型名 = `LoginResult` 的 logic 且被 `/api/auth/` 前缀端点 POST 绑定；
- 生成模板（伪码，注入在原方法 return 之前）：

```java
// M11 鉴权：登录成功 → 签发 token 并回填 LoginResult（生成器注入，TDSL 无感）
String __token = java.util.UUID.randomUUID().toString().replace("-", "");
authTokenRepository.save(new AuthToken(__token, user.getId(), java.time.LocalDateTime.now().plusDays(7)));
result.setToken(__token);
```

- `AuthToken` 过期惰性清理：`issue` 时顺带 `deleteByExpiresAtBefore(now)`（低成本）。

### 2.3 schema.sql

- `auth_token` 表加入 `schemaFiles`（与实体同口径：`token VARCHAR(64) NOT NULL`、`expiresAt TIMESTAMP`）。

### 3.2 `api.ts` / `hooks.ts`

- `apiFile`：`@auth` 应用中所有 `fetch(` → `authFetch(`，文件头 `import { authFetch } from './auth'`；
- `hooks.ts` 不动（401 处理在 authFetch 内，早于 hooks 的 r.ok 分支）。

### 3.3 `routerFile`（App.tsx）

- `@public` 页面：**不进** MODULES/PAGE_MODULE（菜单数据源改为 `routed.filter(v => !isPublic(v))`）；
- Login 页独立渲染：顶栏/侧栏仅在**非公开路由**出现——`useLocation` 判定当前路由是否公开页，是则只渲染 `<Routes>`（全屏企业风卡片页），否则渲染既有 Layout；
- 守卫：受保护路由包 `<RequireAuth><X/></RequireAuth>`（组件在 App.tsx 内生成）：

```tsx
function RequireAuth({ children }: { children: JSX.Element }) {
  const loc = useLocation();
  if (!getToken()) return <Navigate to="/login" replace state={{ from: loc.pathname }} />;
  return children;
}
// 登录页反向守卫：已登录访问 /login → <Navigate to={HOME_ROUTE} />
```

- 顶栏用户区（Layout Header 右侧，`margin-left:auto`）：

```tsx
<div style={{ marginLeft: 'auto', display: 'flex', alignItems: 'center', gap: 12 }}>
  <Avatar style={{ background: '#1677ff' }}>{nickname[0]}</Avatar>
  <span style={{ color: '#fff' }}>{nickname}</span>
  <Dropdown menu={{ items: [{ key: 'logout', label: '退出登录', onClick: () => { clearAuth(); nav('/login'); } }] }}>
    <DownOutlined style={{ color: '#fff' }} />
  </Dropdown>
</div>
```

### 3.4 Login/Register 页面生成（`pageFile` 增量）

- `@public` 页：外层不用 Card 布局，改全屏企业风（渐变背景 + 居中 420px 卡片 + 品牌标题 = 应用名管理系统）；
- `type="password"`：`genInput` 读 `el.props.type === 'password'` → `<Input.Password placeholder="密码" />`；
- **提交后跳转**：表单 submit 绑定的函数 = `login`（loginPage 内）→ 生成提交回调 `setAuth(data.token, data.nickname); nav(HOME_ROUTE)`；registerPage 内 → `nav('/login')`（带「注册成功请登录」toast）。判定用 `@auth.loginPage/registerPage` 显式名字，零推断。

## 6. 交付记录（rv-chg：实施与设计的差异与补全）

<rv-chg>**C1 token 签发判定实现化**：§2.2「按 LoginResult 返回类型约定注入」落为显式口径——`POST /api/auth/*` 端点绑定 + 返回 struct 含 `token` 与 `userId` 字段（注册返回实体不命中）；实现用「公开包装方法 + 私有 inner」而非改 return 语句（多 return 语句天然兼容）。</rv-chg>

<rv-add>**A2 平台鉴权原语（设计缺口补全）**：§4/§5 未覆盖「TDSL 体内调用密码哈希」的机制——PasswordUtil 是生成器产物，TDSL 书写面无法引用。补全自动方案：`FFI_CORE` 新增平台自宿主 **Auth 域**（`Auth.hash(raw, salt)` / `Auth.matches(raw, stored, salt)`，static + backend-only，无 maven 坐标不触发 pom 注入）；java 模板 `__PKG__.support.PasswordUtil.*` 由 codegen 渲染期替换实际包名；`FfiClass.internal` 标记使 import 收集跳过伪类。地位同 `String.trim`（平台自宿主），dev/32"core 只留五域"口径同步更新为「五语言域 + 平台鉴权域」。</rv-add>

<rv-add>**A3 语言边界实测记录**（编码期撞到，均非本切面引入）：①表达式语言无一元 `!`（语法手册 §2 的 "`!`" 实指 `!==`——文档漂移，手册已修）；②块注释 `/* */` 不被 lexer 支持（仅 `//`），样例改行注释；③`List.get(0)` 直取 + 字段访问在 java codegen 无类型通道（get 返回 Object）——login/register 用 for-of（类型推导完备）绕开；`isEmpty` 仅前端域有 js 语义，java 判空用 `count === 0`。</rv-add>

<rv-add>**A4 yudao 实装**：00-model.tdsl（SystemUser `@unique username` + `password`；LoginInput/LoginResult/RegisterInput 三 struct）+ 70-auth.tdsl（@auth + login/register + AuthApi + @public Login/Register 页）+ seed.ts（先注册 admin/登录拿 token，后续全量请求带 Authorization；含「无 token → 401」探针自检，admin 重复注册幂等忽略）+ demo.sh/README 动线（默认账号 **admin/123456**）。</rv-add>
