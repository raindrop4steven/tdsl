# dev/32 系统设计 — 依赖声明与 FFI 目录外置

> 切面：第三方依赖的**声明式引入**（jar/npm + 版本）与**扫描结果外置**。
> 背景：fastjson2 打样时第三方类硬编码进了 `core/stdlib.ts` 的 `FFI_CATALOG`——第三方数据入侵语言核心；pom 依赖注入靠遍历目录 `maven` 字段反推，声明与能力耦合。
> 状态：已交付（2026-09-13；261 单测全绿，fastjson-demo 双端 build ✓，jxc spec 100%）

## 1. 问题陈述

| # | 问题 | 位置 |
|---|------|------|
| P1 | 第三方 jar 的扫描清单（fastjson2 两条）硬编码在语言核心 | `packages/core/src/stdlib.ts:89-102` |
| P2 | pom 依赖注入靠目录反推（codegen 遍历 FFI_CATALOG 收集 maven 字段），非声明驱动 | `packages/codegen-java/src/index.ts:453-483` |
| P3 | `bundle-jar` 产物 JSON 无坐标头，无法与依赖声明关联 | `packages/cli/src/commands.ts:166-207` |
| P4 | typecheck 只认内核目录，工程侧扫描产物没有装载通道 | `packages/typecheck/src/index.ts`（仅 import core 的 ffiByAlias） |

**语言自有域 vs 第三方的边界**：String/Decimal/Date/DateTime/List 五域是语义核类型定义的一部分（TDSL 类型体系的成员表），**属于语言核心，保留**；fastjson2 等一切带 Maven/npm 坐标的类**属于第三方，外置**。

## 2. 设计

### 2.1 依赖声明（DSL 语法，进 AST）

顶层新语句（与 entity/service 同级）：

```
dependency java "com.alibaba:fastjson2:2.0.58"
dependency java "com.fasterxml.jackson.core:jackson-databind:2.17.0" as jackson
dependency npm "antd@^5.21.0"
```

```ts
// core/types.ts 新增
export interface DependencyNode extends BaseNode {
  kind: 'Dependency';
  eco: 'java' | 'npm';
  /** java: groupId；npm: 包名（支持 @scope/name，取最后一个 @ 切版本） */
  name: string;
  /** java: version 段；npm: range（可缺省，缺省 = 用产物坐标版本/最新） */
  version?: string;
  /** `as <ns>`：产物类限定引用前缀（同名类消解，见 2.7） */
  ns?: string;
}
// AppNode 增列：dependencies: DependencyNode[]
```

解析规则：`java` 后单字符串按 `g:a:v` 三段拆；`npm` 后单字符串按最后一个 `@` 拆 name/version（无 `@` 则只 name）。

### 2.2 扫描结果外置（产物格式升级）

`bundle-jar` 产物从裸数组升级为带头对象（旧格式不兼容——自家工具重生成成本为零）：

```json
{
  "eco": "java",
  "coordinate": "com.alibaba:fastjson2:2.0.58",
  "classes": [ { "class": "...", "alias": "...", "frontend": false, "members": [...] } ]
}
```

约定落点：`<工程>/libs/*.json`。npm 侧产物（d.ts 投影，B3）同目录同结构，`eco: "npm"`——本轮只留字段位，不实现。

### 2.3 目录装载与合并（core 纯函数，IO 在外层）

core 不碰磁盘（遵守 codegen 纯函数约定）：

```ts
// core/stdlib.ts 重构后导出
export const FFI_CORE: FfiClass[];            // 五条语言自有域（原 FFI_CATALOG 瘦身）
export function mergeCatalogs(core: FfiClass[], loaded: LoadedCatalog[]): FfiClass[];
// LoadedCatalog = { coordinate, classes }；merge 时产物类补 maven 字段（坐标来自头）
```

loader（读 libs/ 目录 JSON）放 cli / server 的 IO 层，读出后传给 check/generate：

```ts
check(app, { libs?: LoadedCatalog[] })
generateJava(app, { libs?: LoadedCatalog[] })
generateReact(app, { libs?: LoadedCatalog[] })
```

有效目录 = `FFI_CORE ∪ 声明依赖坐标匹配的产物类`。匹配键 = coordinate（eco+坐标全等，版本含在内）。

### 2.4 typecheck 依赖诊断（三条）

| 诊断 | 级别 | 条件 | 口径 |
|------|------|------|------|
| D-dep-1 未声明依赖 | error | 用到有效目录中带坐标的类（非内核五域），坐标未出现在 `app.dependencies` | `请补 dependency java "坐标"` |
| D-dep-2 声明无产物 | warning | 声明了依赖但 libs/ 无匹配 coordinate 产物 | `运行 tdsl bundle-jar 并入扫描结果` |
| D-dep-3 版本漂移 | warning | 声明版本 ≠ 产物 coordinate 版本 | 指出两侧版本 |

### 2.5 codegen 改声明驱动

- **codegen-java**：pom `<dependencies>` = `app.dependencies(eco=java)` 全量注入（内置 spring/web/mybatis 等骨架依赖不变）；删除 FFI_CATALOG 反推逻辑（`collectFfiClassesInExpr` 的 maven 收集仅保留 service import 用途）。
- **codegen-react**：`package.json` dependencies 并入 `dependency npm` 声明（与 component 的 compDeps 同集合去重，声明版本优先）。component 注册仍自动注入（宽松策略不变），`dependency npm` 是显式版本控制渠道。

### 2.7 alias 唯一性与同名类消解

**问题**：不同 jar 常有同名类（fastjson / fastjson2 / jackson 都有 `JSON`）；TDSL 书写面用短名 alias，裸短名撞车必然发生。

**不变式**：有效目录（core 五域 ∪ 全部装载产物）内 **alias 全局唯一**。core 五域占用 `String/Decimal/Date/DateTime/List`，产物 alias 与之冲突同样报错。

**检测**：`mergeCatalogs` 合并时逐对比对 alias，冲突 → 诊断 **D-dep-4**（error），列出冲突 alias 与双方 coordinate，附消解口径。产物内部同名（同 jar 不同包的同简名类）一并检测。

**消解手段（二选一）**：

1. **产物改 alias（首选）**：bundle-jar 产物本就是人工收窄的精选集，直接在产物 JSON 里改 alias（如 `JSON` → `JSON2`）后重编译——零语法成本，适合冲突少时。
2. **声明处命名空间**：`dependency java "g:a:v" as <ns>` → 该产物所有类以 `ns.Alias` 引用（如 `fastjson2.JSON.toJSONString(...)`，对标 M1 `ds.Entity` 限定名）；无 `as` 的产物类保持裸 alias。适合整包隔离（如同时用 fastjson 与 fastjson2）。

**解析链（typecheck）**：`A.m()` → 裸 alias 查有效目录（唯一命中才通过，命中多个报 D-dep-4 口径）；`ns.A.m()` → 先查 `as` 命名空间再查成员。裸名命中多个时，诊断列出各限定形式供改写。

**codegen 不受影响**：java import / js 翻译始终基于 FQN（`cls.class`），alias 只活在 TDSL 书写面与 typecheck 解析层。

### 2.6 示例迁移

用到 fastjson2 的示例工程：补 `dependency java "..."` 语句 + `libs/fastjson2.json` 产物（bundle-jar 重生成）；core 内 fastjson2 常量删除，相关单测迁移。

## 3. 验收标准

1. `core/stdlib.ts` 只含语言自有五域，无任何第三方坐标
2. parser 解析 `dependency` 双 eco → `AppNode.dependencies`（单测）
3. `bundle-jar` 产物带头 coordinate；loader 坐标匹配合并（单测）
4. typecheck D-dep-1/2/3/4 四条诊断（单测，含同名类撞 alias 场景与 `as ns` 消解）
5. codegen-java pom 由声明驱动；codegen-react package.json 合并 npm 声明（单测）
6. jxc 示例：dependency 声明 + libs 产物 → 双端 build ✓
7. `npm test` + `npm run typecheck` 全绿
