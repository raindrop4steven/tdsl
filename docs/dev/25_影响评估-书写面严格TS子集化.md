## 3. 真正的新增成本：tsc 辅助校验线

收敛为 TS 子集后，"tsc 可辅助校验"（D4 收益）才成立，但它不是免费的，需要：

1. **SDK .d.ts 生成器**（新 codegen 目标）：由 entity/struct/logic 生成声明文件（基类 save/delete/where/Page/List/hooks/navigate），即可在一个临时 TS 工程里 `tsc --noEmit` 校验书写面；
2. 部署形态：server 端可跑（Node tsc）；**playground 浏览器内跑 tsc wasm 约 6MB+，建议不做，playground 维持自家 parser 诊断**；
3. 价值定位：tsc 是**第二道宽松网**（语法+类型先验），自家 typecheck 仍是语义核权威（端点暴露/悬空引用等领域约束 tsc 不懂）。NASL 团队同样没有把 tsc 当权威——他们连表达式都自定义。我们反而可以独有这条路。

## 4. 风险清单

- **对拍保质**：48+13 单测重写是最大体力活；建议先改 parser 补"双语法兼容期"（新旧都 parse，新示例锁定），再切默认。
- **JSX 大小写冲突**：TDSL `<table/>` 是领域组件，TSX 中小写 = HTML 原生标签 → 书写面必须 `<Table/>`/`<Column field>` 大写化，agent 提示词与示例都要跟上（一处细节，两套机制分叉点）。
- **LLM 写 TS 但写"错方向"**：严格 TS 子集后模型已知语法，但仍会写出不合法的 **TS**（比如真用 for-in 取值）——自家 parser 诊断依旧不可替代，repair 闭环照旧。
- **历史资产**：文档与教程回写量 ≈ 30% of docs；memory 决策 D4 需重写说明" reversible 撤销过一次"。
