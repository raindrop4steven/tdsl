## 1. 总体架构

外键渲染的唯一事实来源从「codegen-react 现场推断」变为「**AST 语义核直出**」：

```
EntityProp @ref(X, display)      ← parser 语法 + link 短名→nodePath
    │
    ├─ typecheck: F2 校验（ref 目标存在 / display String / 目标需有 queryXxx）
    │
    ├─ codegen-react: 显式链（优先）+ 推断兜底（无注解时不变）
    ├─ codegen-java: 不感知（落库仍 Integer，零改动）
    └─ core: 新增判别节点 ref 字段
```

## 2. 模块改动面

### 2.1 core（types.ts）

- `EntityPropertyNode` 增加可选侧车（不改 TypeRef 判别联合，避免大 switch 爆炸）：

```ts
export interface EntityRefNode {
  kind: 'EntityRef';
  /** 实体 nodePath，link 阶段由短名绑定 */
  entityPath: string;
  /** 显示字段（缺省 = 'name'，typecheck 校验为 String） */
  display: string;
}

export interface EntityPropertyNode {
  ...
  /** M10 外键显式声明（entityPath 由 link 绑定，解析失败仅保留短名由 typecheck 兜底 Diagnostic） */
  ref?: EntityRefNode;
}
```

- package.json 的 switch 穷尽点无需连动（新增的是字段不是节点类型）。**说明**：选择「侧车字段 + 纯接口（无 kind 字面量）」而非判别联合节点，理由：@ref 是属性的修饰数据而非可独立遍历的 AST 节点，避免全仓 switch 穷尽性连环改动。

### 2.2 parser（parser.ts）

- 实体属性注解循环（`parseEntity`）扩展带参注解：`@` 后为 `ref` 时解析 `(短名 [, display: '字段'])`，产出 `{ entityPath: <短名>, display }`：
  - `@ref(Supplier)` → display 缺省 `'name'`（typecheck 阶段校验）；
  - `@ref(er.Supplier, display: 'title')` → 支持限定名；
  - 未知注解仍报错（现有行为不变）；
- `linkApp` 新增第三步：遍历所有 EntityProperty.vol. `ref` → `resolveShort/Qualified` 到实体 nodePath（找不到抛 `TdslSyntaxError`，与 logicRef 绑定失败同款文案风格）；
- 行号：复用 createNode 的行/列（BaseNode），不新增落库面。

### 2.3 typecheck（check 链）

新增校验极（沿用现有六类诊断的第七类 FK-REF）：
| # | 校验 | 诊断 |
|---|------|------|
| R1 | `entityPath` 必须指向 Entity（可能因 link 先抛 Syntax，此层防侧车数据越界） | `FK-REF-ENTITY` |
| R2 | `display` 字段：目标实体存在该属性且类型 primitive String | `FK-REF-DISPLAY` |
| R3 | 目标实体存在无参可用的查询逻辑（`query*` 返回 `List<该实体>`；无参/参数都可空） | warning `FK-REF-NO-QUERY`（提示产出下拉需要它） |
| R4 | 结构体字段与所属实体同名字段携带 ref（genForm 下拉数据源链路的前置假设） | 仅内部断言，不外泄 |

统一收集 routes（emit 出口 + code/suggestion），F2 属于 error 档（阻断 check），R3 为 warning。

### 2.4 codegen-react（显式链 + 兜底）

统一入口函数改造（现有 `fkRefOf` 签名不变，内部加显式分支）：

```ts
function fkRefOf(app, ownerEntName /*兜底用*/, field, opts?: { holderEntity?: EntityNode | null; propRef?: EntityRefNode }): FkRef | null
```

三处消费点的接线改造：

| 渲染点 | 现有 owner 来源 | 新显式来源 |
|--------|----------------|-----------|
| 列表/详情 table 列 | useQuery 返回实体（List 已解包） | 实体 prop 的 `ref` 优先 → options = ref 实体的 queryXxx，label = ref.display |
| 表单字段（dialog Drawer） | bodyStruct + structOwnerEntity | mutation 返回实体 → 同名字段 → prop.ref |
| 明细单元格（repeat） | itemStruct | 单据实体（save 返回实体）同名字段 → prop.ref |

显式优先、推断兜底半引用（@ref 缺 display/无查询逻辑），推断链原样保留——不改既有 jxc/todo 样例行为（回归验收 F3）。

### 2.5 codegen-java

零改动。

### 2.6 接口流程（链式数据流）

```
@ref(sourceDict, display:'name') 解析 → EntityProperty.ref
   → typecheck: R2/R3 通过（字典实体需有 queryCrmSourceDict()）
   → page 生成：collectPageFkRefs 收集（table 列 + form + repeat 三处合一）
   → 生成 hooks：qFkSourceId = useQuery(() => api.queryCrmSourceDict())
   → 渲染：列/表单/明细 Select.options=(qFkSourceId.data ?? []).map(o=>({value:o.id,label:o.name}))
```
