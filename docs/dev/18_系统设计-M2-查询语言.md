# 18 系统设计：M2 —— 查询语言（where 复合条件 / 排序 / 分页 / 聚合）

> 关联：`docs/dev/14_路线规划-NASL对标与前后端能力.md` §4.2（查询语言）、`30_详细设计`（表达式/编译）
> 状态：**阶段二（系统设计）** — 待用户 Gate 确认
> 定位：把 `Entity.where(field = value)` 单等值查询升级为**复合查询语言**——多条件 AND、
> 条件运算符（`=`/`>=`/`<=`/`>`/`<`/`like`/`in`）、链式 `.orderBy()`/`.page()`/`.limit()`、
> 聚合（`sum`/`avg`/`max`/`min`/`count`）+ `groupBy`。对齐 NASL `Query*` 家族，保持 TS 风格书写面。

---

## 1. 目标与验收

### 1.1 现状

- **书写面**：`Entity.where(field = value)` 单等值条件，多条件/排序/分页/聚合全部不支持。
- **parser**：`parsePostfix` 对 `where` 特殊解析，只接受 1 个 `field = value` 参数 → `Binary('=', field, value)`。
- **typecheck**：`checkEntityCalls` 只校验单等值条件（`field = value`）且字段存在。
- **codegen-java**：`collectWhereFields` 收集等值条件字段 → Repository 生成 `findByField(value)` 派生方法；
  `genExpr` where 分支只翻译 `=` 等值。逻辑层无法表达任何复合查询。
- **类型系统**：core `TypeRef` 已声明 `Page` 泛型（`'List' | 'Map' | 'Page'`），但 codegen-java `javaType()`
  对 `Page` 落到默认 `List` 分支（缺失），typecheck 未消费。

### 1.2 达成什么

1. **where 复合条件**：多参数逗号分隔 = AND；单条件支持运算符 `=`/`>=`/`<=`/`>`/`<`/`like`/`in`；
   支持 `&&`/`||` 顶层布尔组合。不带括号分组（嵌套分组标 P1）。
2. **链式排序**：`.orderBy(field asc|desc, ...)` 多字段 → Spring Data 派生方法名 `OrderByXxxAsc/Desc`。
3. **分页**：`.page(n, size)` → 返回 `Page<T>` + Repository 方法带 `Pageable`；
   `.limit(n)` → 返回 `List<T>`（`PageRequest.of(0, n)` 截断）。
4. **聚合**：`Entity.aggregate(sum(field))` / `count()` / `avg(field)` / `max(field)` / `min(field)`；
   可选链式 `.groupBy(field, ...)` → Repository `@Query` JPQL；无 groupBy 返回标量，有 groupBy 返回 `List<Map<String, Object>>`。
5. **类型安全**：typecheck 校验条件字段存在、运算符与值类型匹配、聚合函数参数合法；`Page<T>` 全链路类型正确。

### 1.3 验收标准

- [ ] `curl` 验证**复合查询**：`where` 多条件 + `like` + `in` + `>=` 组合（AND 语义）返回正确行集。
- [ ] `curl` 验证**排序**：`.orderBy(total desc)` 多字段排序结果有序。
- [ ] `curl` 验证**分页**：`.page(n, size)` 返回 `{content, totalElements, ...}`；`.limit(n)` 返回前 n 行。
- [ ] `curl` 验证**聚合**：`sum/count/avg/max/min` 标量结果正确；`groupBy(field)` 返回分组 Map 列表。
- [ ] parser + typecheck + codegen-java + codegen-react（无回归）单测全绿，`npm run slice` 双端构建通过。
- [ ] 不回归 M1/M4/M6 已有能力（`where(orderId = id)` 单等值行为与生成代码不变）。

## 2. TDSL 书写面

```ts
// ---- 复合查询：多条件 AND + 条件运算符 ----
@export
logic searchOrders(customer: String, minTotal: Decimal): List<Order> {
  return Order.where(customer like '%' + customer + '%', total >= minTotal);
}

// ---- in 集合 ----
@export
logic queryByStatus(statuses: List<String>): List<Order> {
  return Order.where(status in statuses);
}

// ---- 排序：.orderBy(field asc|desc) 多字段 ----
@export
logic topOrders(): List<Order> {
  return Order.where(total > 0).orderBy(total desc, id asc).limit(10);
}

// ---- 分页：.page(n, size) → Page<T> ----
@export
logic pageOrders(n: Integer, size: Integer): Page<Order> {
  return Order.where(total > 0).orderBy(total desc).page(n, size);
}

// ---- 聚合：标量 ----
@export
logic orderTotal(): Decimal {
  return Order.aggregate(sum(total));
}

// ---- 聚合：count ----
@export
logic orderCount(): Integer {
  return Order.aggregate(count());
}

// ---- 聚合 + groupBy → List<Map<String, Object>> ----
@export
logic sumByCustomer(): List<Map<Object>> {
  return Order.aggregate(sum(total)).groupBy(customer);
}
```

**语法规则**：

| 形态 | 规则 |
|---|---|
| `where(cond1, cond2, ...)` | 逗号分隔多条件 = **AND**；空参报错 |
| 条件 | `field op value`，op ∈ `=`/`>=`/`<=`/`>`/`<`/`like`/`in`；`value` 可为变量/字面量/列表 |
| `&&`/`||` | 顶层布尔组合（`a = 1 && b >= 2` 等）；括号分组 P1 |
| `.orderBy(f asc|desc, ...)` | 多字段，`asc`/`desc` 为方向关键字（仅限 orderBy 参数位） |
| `.page(n, size)` | 收尾方法，返回 `Page<T>`；与 `.limit` 二选一 |
| `.limit(n)` | 收尾方法，返回 `List<T>` |
| `Entity.aggregate(fn(…))` | fn ∈ `sum(f)`/`avg(f)`/`max(f)`/`min(f)`/`count(f)`/`count()`；单参数单聚合（多聚合 P1） |
| `.groupBy(f, …)` | 聚合后可链，返回 `List<Map<String, Object>>`；不可与标量聚合同时使用 |

**与 NASL 对齐**：`where` ≈ `QuerySelectExpression`+`QueryFieldExpression`，`.orderBy` ≈ `QueryOrderByExpression`，
`.page`/`.limit` ≈ `QueryLimitExpression`，`aggregate`/`groupBy` ≈ `QueryAggregateExpression`+`QueryGroupByExpression`。

## 3. IR 变更（core）

### 3.1 Binary operator 扩展

`expr.ts` 的 `Binary.operator` 联合新增：

```ts
| 'like'
| 'in'
```

- `like`：左=字段 Ident，右=模式表达式（String/变量拼接，运行期 `%…%` 由书写面决定是否包裹）。
- `in`：左=字段 Ident，右=集合（变量 `List<T>` 或数组字面量）。

### 3.2 NewList 支持数组字面量

`NewList` 节点已有 `elem: TypeRef; items: Expr[]`。新增**数组字面量语法** `[...]`：

```ts
Order.where(status in ['A', 'B', 'C']);
```

- parser 的 `parsePrimary` 增加 `[` 分支，元素逗号分隔 → `NewList { elem: 首元素推断类型, items }`；
  空数组 `[]` 在 `in` 语境 elem 推为右值变量元素类型（运行时集合归一）。
- `NewList` 已存在于 core/parser/codegen 的穷尽分支中，无需新增节点类型。

### 3.3 Page 类型语义

`Page<T>` 已是合法 TypeRef（泛型），无需改 core。本里程碑补齐消费端：
- codegen-java `javaType()`：`Page` → `org.springframework.data.domain.Page<T>`。
- typecheck：`Page<T>` 作为 logic 返回类型合法（校验 T 为实体），并推导 where 链返回类型。

### 3.4 不新增查询节点

链式 `.orderBy/.page/.limit/.groupBy` 用现有 `Call(Member(...))` 表达（与 `where` 同构），
typecheck/codegen 通过「接收者是否为实体静态查询调用」识别链式组合，避免新增穷尽分支。

## 4. parser 变更

### 4.1 where 多条件解析

`parsePostfix` 的 where 特殊分支重写为 `parseWhereArgs()`：

1. 循环 parse 条件，直到 `)`：
   - parse 左操作数（Ident 字段）；
   - 探测运算符 token：`=`/`>=`/`<=`/`>`/`<` 走二元；`like`/`in` 为 ident 关键字探测；
   - parse 右操作数（表达式；`in` 右操作数支持 `[...]` 数组字面量）；
   - 若不匹配任何运算符 → 报错「where 条件必须是 field op value」。
2. 条件间 `,` 分隔 → 多个 `Binary`；`&&`/`||` 在条件后探测 → 顶层 `Binary('&&'/'||', left, right)` 组合。
3. 参数 ≥ 1，否则报错。

### 4.2 链式方法解析

where/aggregate 调用返回后，`parsePostfix` 继续探测后续 Member-Call：

- `.orderBy(...)`：参数交替为 [Ident 字段, 方向关键字 `asc`/`desc`]，方向关键字在参数位转成 `String('asc'/'desc')` 字面量
  （不引入新节点）；字段必须 Ident。
- `.page(n, size)` / `.limit(n)`：普通表达式参数，尺寸 ≥ 1。
- `.groupBy(...)`：字段 Ident 列表。
- 渲染为嵌套 `Call(Member(innerCall, method), args)`，与现有 where 调用兼容。

### 4.3 aggregate 解析

`Entity.aggregate(...)` 参数为单调用表达式：`sum(f)`/`avg(f)`/`max(f)`/`min(f)`/`count(f)`/`count()`。
- `sum/avg/max/min` 内参数为字段 Ident；`count` 可无参或字段。
- 表达为 `Call(Member(Ident(Entity), 'aggregate'), [Call(Ident('sum'), [Ident(field)])])`，
  typecheck/codegen 侧识别 `aggregate` 调用内层。

## 5. typecheck 变更

`checkEntityCalls` 的 where 分支扩展为 `checkWhere(recvName, args)`：

1. **条件遍历**：顶层 `&&`/`||` 二叉递归；叶条件必须是 `Binary` 且：
   - operator ∈ {`=`, `>=`, `<=`, `>`, `<`, `like`, `in`}；
   - 左操作数为 Entity 字段 Ident → 字段存在性校验（沿用现有）；
   - 右操作数类型可赋予字段类型（`=`/比较）或为 String（`like`）或集合（`in`）。
2. **链式识别**：`Member` 接收者为实体静态查询调用（`where`/`all`）时，`.orderBy/.page/.limit` 参数形态校验：
   - orderBy 参数偶数个，奇数位 Ident 存在，偶数位为 `'asc'/'desc'` 字面量；
   - page 2 参、limit 1 参，均为数值。
3. **返回类型推导**：
   - where 链 → `List<Entity>`；带 `.page()` → `Page<Entity>`（exprType 同步）；
   - `aggregate(sum(f))` 标量 → `Decimal`（sum/avg）、`Integer`（count）、字段类型（max/min）；
   - `aggregate(...).groupBy(...)` → `List<Map<Object>>`（映射 `java.util.Map<String, Object>`，泛型参数 `Object`）。
4. **Page 返回合法性**：logic 返回类型含 `Page<T>` 时校验 T 为实体，且 return 表达式为带 `.page()` 的查询链。

## 6. codegen-java 变更

### 6.1 查询规格收集（替代 collectWhereFields）

新增 `QuerySpec` 结构，收集每个实体上**所有查询形态**（去重）：

```ts
interface QuerySpec {
  entity: string;
  conditions: Array<{ field: string; op: '='|'>='|'<='|'>'|'<'|'like'|'in'; valueKind: 'param'|'literal'|'list' }>;
  orderBy: Array<{ field: string; dir: 'asc'|'desc' }>;
  pageable: boolean;       // .page()/.limit() 需要 Pageable
  limit?: number;
  aggregate?: { fn: 'sum'|'avg'|'max'|'min'|'count'; field?: string };
  groupBy?: string[];
}
```

- 遍历 app.logics 全部查询调用链（沿用 `forEachStmt` 递归），归一化为 QuerySpec。
- 同规格去重（同条件集+排序 → 同一方法名）。

### 6.2 Repository 方法生成策略

对每个 QuerySpec 生成 Repository 方法：

| 形态 | 生成方式 |
|---|---|
| 单 `=` 条件（现行为） | `List<T> findByField(Type field)` — **保持不变，零回归** |
| 多条件 AND + 排序（无聚合） | 派生方法名拼接：`findByAAndBOrderByCDesc`；`like`→`…Like`、`in`→`…In(Collection)`、`>=`→`…GreaterThanEqual` |
| 带 `.page()` | 同派生名，方法参数追加 `Pageable pageable`，返回 `Page<T>` |
| `.limit(n)` | 返回 `List<T>`，追加 `Pageable`（Service 传 `PageRequest.of(0, n)`） |
| 聚合（无 groupBy） | `@Query("SELECT SUM(e.total) FROM Order e")` 返回 `BigDecimal`/`Long`/字段类型 |
| 聚合 + groupBy | `@Query("SELECT e.customer, SUM(e.total) FROM Order e GROUP BY e.customer")` 返回 `List<Object[]>`，Service 组装 `Map<String,Object>` |

- 相邻 AND 派生名冲突（如 `findByAAndB` 与字段 `aAndB`）→ 方法名加 `Q1/Q2` 后缀（OrderBy 关键字段冲突同理）。
- `in` 参数类型：若条件值来源为 `List<String>` 变量 → `Collection<String>` 参数；字面量数组 → `java.util.List<T>`。

### 6.3 genExpr 翻译

- where 链 → `repo.findBy…(params…)` / `repo.findBy…(params…, PageRequest.of(n, size))`；
  `.getContent()` 仅 `.limit` 或非 page 场景按返回类型裁剪（`Page` 返回直接透传）。
- 聚合标量 → `repo.sumTotal()` 等；groupBy → `repo.sumTotalByCustomer()` 返回 `List<Map<String,Object>>`。
- `javaType()` 增加 `Page` 分支：`org.springframework.data.domain.Page<T>`。

### 6.4 Service 生成

- 返回类型含 `Page<T>` 的 logic → Service 方法返回 `Page<T>`，构造 `PageRequest.of(n, size)`。
- 聚合标量 logic → Service 方法返回 `BigDecimal`/`Long`。
- groupBy logic → Service 内把 `List<Object[]>` 转为 `List<Map<String, Object>>`（行序=groupBy 字段 + 聚合列）。

## 10. 边界与后续（P1）

- 括号分组：`where(a = 1 && (b = 2 || c = 3))` → 需 Specification/Criteria，标 P1。
- 多聚合参数 `aggregate(sum(a), avg(b))`、聚合带 where 条件 → 标 P1。
- `Page<T>` 前端分页 UI/组件 → 标 P1。
- SQL 动态参数化/防注入：本里程碑全部走 Spring Data 派生参数绑定或 JPQL `:param`，无字符串拼接注入面。
