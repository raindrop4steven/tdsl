# 30_系统设计-A1-异常与错误表达

> <rv-add>2026-09。定位：语言层最后一块大件——logic 里没有 try/throw，业务失败目前只能 return false（信息丢失、错误不可定位、LLM 书写不体面）。
> 与既定分界一致：**抛出是后端事务语义**（前端不 catch），expression 复用共享小语言。</rv-add>

---

## 1. 决策（D-ERR1~4）

| # | 决策 |
|---|------|
| D-A1-1 | **`throw <expr>;`** 语句（expr 复用共享表达式语言；v1 限定标量消息 String/userset） |
| D-A1-2 | Java 生成：TDSL 框架类 `TdslError(code, message)` + **@RestControllerAdvice** 统一映 HTTP 4xx（业务错误）——不是裸 RuntimeException |
| D-A1-3 | logic 间调用的错误传播：受调方 throw → 调用方不 catch（v1 无 try 语句；错误向上冒泡到端点） |
| D-A1-4 | 前端 api.ts/hooks 不动：非 2xx → fetch 已进 error 路径（现有 hooks.error 兜底，UI 面板展示） |

> try/catch 本身**不做**：企业规则里“可预期的业务失败”应表达为 Return 值或 TdslError 通道；不可预期失败交给统一 Handler。少而闭包。

## 2. 语法

```tdsl
@export
function submitPurchaseBill(id: Integer): Boolean {
  bill := PurchaseBill.get(id);
  if (bill.status !== DocStatus.DRAFT) {
    throw '仅暂存单可提交';           // → 400 {code: 'GENERIC', message: '仅暂存单可提交'}
  }
  …
}
```

## 3. 实施清单

- core：`Throw` 语句节点（= Statement 判别联合新增）
- parser：`throw <expr>;` 语句
- typecheck：throw(expr) 表达式仅标量/成员纯计算（沿用 FFI 目录）；throw 在 logic 体内合法
- codegen-java：Throw → `throw new com.<pkg>.support.TdslError("<msg>")`；scaffold 补 TdslError + 全局 advice
- codegen-react：api.ts fetch 的 4xx 解出 advice body 到 hooks.error（现有 error 展示面复用）
- 单测：parser/typecheck/codegen-java 三面 + jxc 打样点（submitPurchaseBill 改 throw 语义）
