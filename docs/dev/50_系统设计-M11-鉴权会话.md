## 1. 设计总则

1. **声明驱动**：`@auth(...)` 是唯一开关——**无 `@auth` 的应用，双端生成产物逐字节不变**（护栏，测试锁死）。
2. **框架代码归生成器**：令牌表、拦截器、密码工具、会话守卫、顶栏用户区与 `HealthController` 同一地位（生成器产出，不写成 TDSL entity/page）。
3. **业务归 TDSL**：注册/登录仍是普通 `function` + `interface`（查重/校验/建号写在 logic 里），编译器只提供「鉴权原语」。
4. **零新依赖**：随机 token = `java.util.UUID`；密码哈希 = JDK `MessageDigest`（SHA-256 + 用户名盐）；前端沿用 react-router/antd。

## 2. 模块架构（改动面总览）

```
TDSL                          生成物（Java）                    生成物（React）
─────────                     ─────────────                    ──────────────
@auth(user/username/password)─▶ AuthProperties（常量）          ─▶ auth.ts（token 存取 + 401 处理）
@public page Login/Register   ─▶ /api/auth/** 放行（拦截器内）   ─▶ 布局外全屏页 + 路由守卫
function login/register       ─▶ Service 方法（普通生成）        ─▶ api.ts login/register
interface AuthApi             ─▶ AuthController（普通生成）      ─▶ 顶栏用户区（App.tsx 顶栏右侧）
（无 TDSL 形态）              ─▶ AuthToken entity + Repository  ─▶ localStorage token
（无 TDSL 形态）              ─▶ AuthInterceptor（401 横切）     ─▶ <Navigate> 守卫
（无 TDSL 形态）              ─▶ PasswordUtil（SHA-256+盐）      ─▶ useAuthState
```

| 包 | 新增/改动 | 关键点 |
|----|-----------|--------|
| core | `AppNode.auth?: AuthConfigNode`（侧车字段） | `AuthConfigNode { userPath, usernameProp, passwordProp }`（nodePath 引用，resolve 校验） |
| parser | 顶层 `@auth(k=v,...)` 解析（复用 parseServiceConfig 的 KV 形态）；`@public` 页面注解；`input` 的 `type` 属性透传 | `@public` 存 `view.annotations`，与 `@title/@menu` 同机制 |
| typecheck | AUTH-\* 三码：实体存在/字段存在且 String/唯一约束建议；`@public` 与 `@auth` 缺失冲突 | 宽松策略：可判则判，可判不出放行 |
| codegen-java | `authFiles(app)`：AuthToken entity + Repository + AuthInterceptor + PasswordUtil + WebMvcConfig；`login/register` Service 注入 PasswordUtil 与 token 签发 | 有 `@auth` 才生成；拦截器注册走 `WebMvcConfigurer` |
| codegen-react | `authTsFile`（auth.ts）+ api.ts 头注入 + routerFile 守卫分支 + 顶栏用户区 + Login/Register 布局外渲染 + input type=password | 无 `@auth` 走原分支（逐字节不变） |

## 3. 数据流（登录 → 携 token 访问 → 401 回流）

```
① 登录     POST /api/auth/login {username,password}
             └▶ TDSL function login：User.where(username=x) → 校验 PasswordUtil.matches
             └▶ 生成器注入的 TokenService.issue(userId) → AuthToken 入库 → 返回 {token, nickname}
② 存储     前端 auth.ts：localStorage.setItem('tdsl_token', token)（+ 当前用户）
③ 携带     api.ts 每个 fetch 统一 headers: { Authorization: 'Bearer ' + getToken() }
④ 校验     AuthInterceptor：路径不在放行名单 → 取 Bearer token → 查 AuthToken 表
             ├ 命中未过期 → 放行（ThreadLocal 挂 currentUser 供业务取用）
             └ 未带/无效/过期 → 401 {"message":"未登录或登录已过期"}
⑤ 回流     前端 fetch 封装见 401 → auth.ts 清 storage → location → '/login'
```

## 4. 接口与端点设计

| 端点 | 方法 | 入参 | 出参 | 归属 |
|------|------|------|------|------|
| `/api/auth/register` | POST | `RegisterInput{username,password,nickname}` | `SystemUser` | TDSL `interface AuthApi`（业务） |
| `/api/auth/login` | POST | `LoginInput{username,password}` | `LoginResult{token,nickname,userId}` | TDSL `interface AuthApi`（业务） |
| 其余 `/api/**` | * | — | 401 若无有效 token | 生成器拦截器（框架） |
| `/healthz` | GET | — | 200 | 既有探针（放行） |

- `LoginResult`/`RegisterInput`/`LoginInput` 是普通 struct（TDSL 声明）；
- **token 签发不进 TDSL**：`login` function 里写 `Auth.issue(userId)`？——否。生成器在 login 端点接线处**按返回类型约定注入**：凡 `@auth` 应用中，`POST /api/auth/login` 绑定的 function 返回 `LoginResult`，生成器在其 Service 方法尾部注入 `token = tokenService.issue(user.id)` 并回填。TDSL 书写面不出现 token 概念（写 TDSL 的人感知不到令牌管理）。
- 放行名单推导：`/healthz` + 该应用 `interface` 中路径前缀 `/api/auth/` 的端点（自动，无需再声明）。

## 5. 关键机制设计

### 5.1 Java 端（authFiles 清单）

| 文件 | 职责 |
|------|------|
| `entity/AuthToken.java` + `repository/AuthTokenRepository.java` | `token/userId/expiresAt`；token 列唯一索引；过期清理（查询时惰性删除） |
| `support/PasswordUtil.java` | `hash(password, salt)` / `matches(raw, hash, salt)`，SHA-256 + Base64；盐 = username |
| `support/AuthInterceptor.java` | `HandlerInterceptor`：放行名单外校验 Bearer；`request.setAttribute('currentUser', userId)` |
| `support/WebMvcConfig.java` | 注册拦截器 + 放行名单（`/healthz`、`/api/auth/**`、error） |
| `service/*Service.login` 注入 | 调 `PasswordUtil.matches`；签发 token（7 天过期）写入 AuthToken；组装 `LoginResult` |

### 5.2 React 端

| 文件/机制 | 职责 |
|-----------|------|
| `src/auth.ts` | token/用户存取（localStorage）、`authFetch` 头注入、401 统一回流 |
| `src/api.ts` | 所有 fetch 改走 `authFetch`（仅 `@auth` 应用；无 `@auth` 保持原 fetch） |
| `src/App.tsx` | 守卫：非 `@public` 路由包 `<RequireAuth>`；顶栏右侧用户区（Avatar + Dropdown 退出）；已登录访问 /login 重定向 |
| `src/pages/Login.tsx / Register.tsx` | 布局外全屏企业风卡片页；`@public` 页不进 MODULES/PAGE_MODULE |
| hooks.ts | `useMutation` 的 okMessage 机制不变；登录成功跳转由 Login 页提交回调处理（表单 submit 成功后 navigate） |

### 5.3 「登录成功后跳首页」的实现口径

`useMutation` 不扩展 onSuccess（避免动全局语义）。Login 页表单提交绑定 `useMutation('login')` 成功后：
- 生成器对 `@public` 且**路径为登录页**（`@auth` 声明的应用中名为 Login 的公开页）的表单提交生成「成功 → `nav(HOME)`」回调；
- 同理 Register 成功 → `nav('/login')`。
- 判定显式：登录页 = `@auth` 应用中带 `@public` 的 `page Login`（名字约定在 `@auth` 里声明，如 `@auth(..., loginPage: 'Login', registerPage: 'Register')`，避免猜名字）。

### 5.4 typecheck 诊断（AUTH-\*）

| 码 | 级别 | 条件 |
|----|------|------|
| AUTH-USER | error | `@auth.user` 指向实体不存在 |
| AUTH-FIELD | error | username/password 字段缺失或非 String |
| AUTH-PAGE | error | `loginPage/registerPage` 指向的页面不存在或未标 `@public` |
| AUTH-UNIQUE | warning | username 字段未标 `@unique` |

## 6. 兼容与护栏

1. 无 `@auth`：core/parser 产出不带 auth；typecheck 零新诊断；**双端生成物与现状逐字节一致**（快照断言）。
2. 有 `@auth`：新增文件集中在 `auth/` 域，既有模板改动收口在「fetch 头注入」「routerFile 守卫」「顶栏用户区」三处，均有独立测试。
3. seed/eval/runner 兼容：seed 先调登录拿 token（demo.sh 动线更新）；eval 打分样卷不受影响（无 @auth）。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 拦截器与 GlobalAdvice 异常路径冲突 | 拦截器 401 直接写响应（不走异常），`/error` 入放行名单 |
| 密码哈希改动导致既有用户登录失败 | 本切面引入鉴权时 erp 库用户表尚无哈希口径（seed 全新灌入），一次性切换 |
| localStorage XSS 面 | 演示级口径写入文档；真实商用另立切面（HttpOnly Cookie） |
| react 生成物改动引发 jxc/todo 快照回归 | A10 逐字节不变护栏 + 快照测试先行 |
