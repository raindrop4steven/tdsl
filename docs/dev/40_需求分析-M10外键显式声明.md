# 40 · 需求分析 — M10 外键显式声明语法（@ref）

> 状态：⏸ 待用户 Gate 确认（阶段一·需求分析）
> 日期：2026-09-16
> 关联：dev/39（芋道 ERP/CRM 能力验证）、dev/12（M2 查询语言）、M1 命名空间（命名空间限定名）

## 1. 背景

芋道示例接入过程中，前端列表「裸列 id 数字」与表单「让人填数字」的问题暴露了目前外键处理的机制边界：

| 问题表现 | 根因 |
|----------|------|
| 采购单列表「供应商」列显示 `1`，编辑时要求手填数字 id | codegen 纯靠**字段名推断**外键（`xxxId` 命名） |
| 线索列表「线索来源」永远是数字 | 字段名 `source`（非 `sourceId`）且指向**数据字典**，工程内无对应实体/查询逻辑，推断无从猜起 |
| 产品列表「产品分类」可以下，因为 `categoryId` 命名规范 + 存在 `queryErpProductCategory` | 推断法出效果的前提刚好都成立 |

现行推断规则（codegen-react 内，纯启发式）：
1. 字段名以 `Id` 结尾 → 外键，取 stem；
2. 在实体表中找同名/同后缀实体；多命中时「域 token（options 逻辑名前缀）→ owner 公共前缀最长 → 最短候选」三级消歧；
3. 候选若无无参查询逻辑或显示字段（`name`/首个 String），退回数字。

结论：**能猜的已经猜好；猜错/猜不出的（字典字段、命名不规范的表间引用），必须语法层面显式声明。**

## 2. 目标

- **F1（主）**：TDSL 实体字段支持显式外键声明 `@ref(<实体引用>, [display])`，覆盖「列表列显示引用名 / 表单下拉 / 明细行下拉」三处渲染。
- **F2**：typecheck 校验 `@ref`：目标实体存在、display 字段是 String；悬空引用升级为 Diagnostic（不再静默）。
- **F3**：推断逻辑降级为兜底：有 `@ref` 优先 @ref；无注解时沿用现有推断（保持旧样例零改动可用）。
- **F4（配套字典建模）**：芋道样例补字典实体（`ErpDict`/`CrmDict` 归并?）用于 `source`/`industryId`/`areaId` 等字典字段，并 `@ref` 声明之。

## 3. 词法形式（草案，以设计阶段定稿为准）

```tdsl
entity CrmClue {
  id: Integer @pk;
  name: String;
  source: Integer @ref(sourceDict);              // 引用实体 sourceDict，显示默认取其 name
  industryId: Integer @ref(industry, display: 'name');
  supplierId: Integer;                            // 无注解 → 沿用现有推断
}
```

约束：
- 目标必须是实体类组件（不允许引用结构体/枚举——枚举直接用 `status: EnumKind`）；
- `display` 缺省取目标实体 `name` 字段；
- 引用按 nodePath 说话（`app.datasources.yudaoDS.entities.Supplier`），与 M1 一致。

## 4. 非目标（本迭代不做）

- 不做多级关联展示（如列里同时引用两级 `@ref(order.customer.name)`）；
- 不改落库行为：实体 Java 侧仍为普通数值列（codegen-java 不感知 @ref 走 excluded 简化路径）；
- 不自动生成缺失的 options 查询逻辑（typecheck 对「引用了无查询逻辑的实体」报警告，提示补逻辑——本期芋道 supplier 已补好先例）。

## 5. 验收标准（阶段五测试依据）

| # | 场景 | 预期 |
|---|------|------|
| A1 | 列表列具 `@ref` 字段 | 渲染引用实体 display 值，非数字 |
| A2 | 表单字段具 `@ref` | antd Select 下拉，label = display 值 |
| A3 | 明细行（repeat 单元格）具 `@ref` | 选择器单元格 |
| A4 | `@ref` 指向不存在实体 / display 字段不存在/非 String | typecheck Diagnostic（nodePath + 行列） |
| F3 回归 | 无注解字段（如现有 todo/jxc/yudao 既有样例） | 推断链照旧，全部既有单测通过 |
| A5 | 芋道 source/industryId/areaId | 字典实体 + @ref 后全链路可选中、显示中文名 |

## 6. 外部依赖

- core 判别联合新增 `PropertyNode.ref` 字段（或 TypeRef 侧车），switch 穷尽点会被 TS 编译器强制收敛；
- 不新增 npm/java 依赖。

## 7. 风险

| 风险 | 应对 |
|------|------|
| 解析 `@ref(X, display)` 与既有 `@pk`/`@nullable` 注解文法融合 | parser 注解面统一支持参数（`args[kv]`） |
| 芋道字典建模牵动 seed 数据 | 字典实体数据并入 seed.ts 一次灌入 |
| 推断兜底与显式 ref 冲突 | 显式优先，推断只处理未注解字段 |
