## 2. 失败分类（从产物抽查发现，价值大于数据）

| 类别 | 现象 | 归宿 |
|------|------|------|
| **parse 语法长尾** | `form submit={…}` / 按钮属性词法上 LLM 偶发写错（如 `expected ')' but got '='`） | cheatsheet 的按钮/表单绑定词法段收紧 + repair 闭环保留 |
| **FFI 类型精析**（存量余项重现） | LLM 想走 `@service bean` SDK 通道调 fastjson2，返回 `Object` 后 `.containsKey` 在 Java 里找不到符号 | **dev/27 余项**：javap descriptor 精析（目录类型级映射）+ Object cast 语法 |
| **非确定性波动** | 同卷重跑一次首轮全过一次 3 轮才过 | 评测结果按多次运行聚合（矩阵式），次轮跑再对拍 |
| 正常面 | 纯函数查询/枚举/接口/双端构建都能自然落位（库存汇总/finance/fastjson2-demo 首轮即绿） | 主线证明 LLM 与 TS 词法面新语法配合良好 |

## 3. 两个真实的细粒度发现（为什么 C4 是"第一份"）

1. **OpenCode Go 网关要求 x-opencode-session 请求头**——M10 的踩坑在评测器重现（provider 首版 0/7 都卡此路），修复后 todo 样例 2 轮修复收敛 → 证明"修复循环"对常见语法面有效。
2. **build 通过是独立的统计面**——首轮绿≠构建绿（如 fastjson2-demo 的 react 骨架在无实体 app 场景缺失 → main.tsx 条件化后双通过）。**build 通过率在 v1 硬指标里要用抽验样例记**，不能想当然。

## 4. 结论与下一步（本轮 Instrument 本身已可复用）
