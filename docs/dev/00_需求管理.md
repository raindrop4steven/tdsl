## 1. 目标（为什么做这个切面）

在项目仅有设计文档（零代码）的前提下，用**最小工作量**验证 P0 闭环成立：

> **TDSL（TS 书写面）→ parser → Typed AST → typecheck → codegen → React/Java 产物真实 build 通过**

验证的核心风险点：
1. TS 书写面（LLM 本能语法）能否被干净地 parse 成 Typed AST？
2. 同一份 AST 能否翻译成两端**可编译**的代码（语义一致性）？
3. 判别联合 + `never` 穷尽设计是否在真实编码中成立？

## 2. 范围（切面边界）

### 2.1 范围内（本次要做）

| 模块 | 内容 | 验收 |
|------|------|------|
| `packages/core` | Typed AST：App/Entity/Structure/Enum/TypeRef + 最小 Expr/Statement | 类型定义 + 构造工具 |
| `packages/parser` | TDSL 书写面子集 → AST（实体/结构/枚举/一个 logic） | 单测通过，错误带行列 |
| `packages/typecheck` | 最小版：引用 resolve 绑定 + 基本赋值兼容 | 悬空引用/类型不匹配报 Diagnostic |
| `packages/codegen-java` | 生成完整 Spring Boot 工程（Entity→JPA、Logic→Service） | `mvn compile` exit 0 |
| `packages/codegen-react` | 生成完整 Vite 工程（Entity→TS 类型、View→TSX 组件） | `vite build` exit 0 |
| `examples/todo-app` | `todo.tdsl` 输入 + 闭环驱动脚本 `slice.ts` | 一条命令跑通 + 双端 build |

### 2.2 范围外（本次明确不做）

- JSON AST 序列化 / schema 包 / round-trip 测试（P1+）
- Interface/Endpoint → Java Controller + React axios/hooks 数据流（P1）
- 完整 typecheck（类型推导、泛型统一、隐式转换全量）——只做最小绑定+兼容
- View/JSX 解析（React 端只生成静态列表组件，数据用模拟 fetch）
- 前端/后端真实联通（两端各自 build 通过即验收）
- LLM 集成、CLI、playground（P2）

### 2.3 默认取舍

- Demo 领域用 **Todo**（P0 清单明确"一个端到端示例（Todo）"；E2E 场景1 的 Product 仅作示例）
- 包管理用 **npm workspaces**（本机无 pnpm；文档允许 npm/pnpm）

每个 Gate 用 question 工具三选一确认：确认通过 / 还要修改 / 先放一放。

## 5. 验收标准（需求层面，继承自 10_需求设计 §5 裁剪）

1. 一段 `todo.tdsl` → 端到端产出**可编译**的 React + Java 工程。
2. parse/typecheck 错误带 nodePath 与行列，可定位。
3. 同一份 Typed AST 分别生成 React 与 Java，语义一致（字段/类型/调用对应）。
4. 新增节点类型时，生成器 `never` 穷尽强制编译报错。
