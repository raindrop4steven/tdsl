## 2. 业务场景（TDSL 书写面）

```ts
// ---- 扁平表：两个平等实体，通过普通外键字段 orderId 关联 ----
entity Order {
  id: Integer @pk;
  customer: String;
  total: Decimal;          // 汇总金额（Decimal 精确小数）
}

entity OrderItem {
  id: Integer @pk;
  orderId: Integer;        // 外键 → Order.id（普通字段，无主子表概念）
  product: String;
  price: Decimal;
  qty: Integer;
}

// ---- 入参 / 出参结构 ----
struct OrderInput {
  customer: String;
  items: List<OrderItemInput>;   // 关联明细行集合
}
struct OrderItemInput {
  product: String;
  price: Decimal;
  qty: Integer;
}
struct OrderDetail {
  order: Order;
  items: List<OrderItem>;        // 按外键查出的关联集合
}

// ---- 复杂逻辑：事务创建 + 循环累加 + 校验 ----
@export
logic createOrder(input: OrderInput): Order {
  if (input.items.count === 0) {   // List.count 校验明细非空
    return null;
  }
  order := new Order();
  order.customer = input.customer;
  order.total = 0;
  order.save();                    // 先落订单头，拿到 id
  for (it in input.items) {
    item := new OrderItem();
    item.orderId = order.id;       // 外键关联
    item.product = it.product;
    item.price = it.price;
    item.qty = it.qty;
    item.save();
    order.total = order.total + it.price * it.qty;   // 累加：Decimal 乘法 + 加法
  }
  order.save();                    // 回写汇总金额（同一事务）
  return order;
}

// ---- 复杂逻辑：按外键查关联集合并组装返回 ----
@export
logic getOrderDetail(id: Integer): OrderDetail {
  order := Order.get(id);
  detail := new OrderDetail();
  detail.order = order;
  detail.items = OrderItem.where(orderId = id);   // where 查询
  return detail;
}

// ---- 复杂逻辑：级联删除（先删关联，再删主） ----
@export
logic deleteOrder(id: Integer): Boolean {
  order := Order.get(id);
  for (it in OrderItem.where(orderId = id)) {
    it.delete();
  }
  order.delete();
  return true;
}

// ---- 简单列表 ----
@export
logic listOrders(): List<Order> {
  return Order.all;
}

interface OrderApi {
  GET    '/api/orders'          -> listOrders
  POST   '/api/orders'          -> createOrder
  GET    '/api/orders/{id}'     -> getOrderDetail
  DELETE '/api/orders/{id}'     -> deleteOrder
}
```

## 3. 语义：扁平表 + 外键关联（非主子表）

| 概念 | 说明 |
|------|------|
| 平等表 | `Order` / `OrderItem` 都是普通实体，无"主/子"层级 |
| 外键字段 | `OrderItem.orderId: Integer` 是**普通标量字段**，不是引用类型导航 |
| 关联查询 | 用 `OrderItem.where(orderId = id)` 显式按外键查集合 |
| 无导航属性 | 不做 `order.items` 魔法导航（对比 P1 方案 A，已否决） |

## 4. DSL 语法扩展

### 4.1 运算符（parser/typecheck/genExpr 联动）

当前只支持 `+` `<` `<=` `===` `!==` `&&` `||`。本切面补齐：

| 新增运算符 | 说明 |
|-----------|------|
| `-`（减法/取负） | 算术 |
| `*`（乘法） | 算术（算总价必需） |
| `/`（除法） | 算术 |
| `>`（大于） | 比较 |
| `>=`（大于等于） | 比较 |

- parser：`parseAdditive`/`parseRelational` 补齐运算符分支。
- lexer：确认 `-` `*` `/` `>` `>=` token 存在。
- typecheck：新运算符的左右操作数类型兼容性（如 `Decimal * Integer` → `Decimal`）。
- genExpr：运算符 → Java；**Decimal 特殊处理**（见 §7）。

### 4.2 List 方法

| 方法 | 语义 | Java |
|------|------|------|
| `list.count` | 元素个数 | `.size()` |
| `list.add(x)` | 追加元素 | `.add(x)` |

- 语义识别（不改 Expr 结构）：`Call(Member(list,'add'), [x])`、`Member(list,'count')`。
- typecheck：`.count` 接收者必须是 List；`.add` 参数须可赋给元素类型。
- genExpr：`.count` → `.size()`；`.add` → `.add()`。

### 4.3 where 查询（新语法，核心）

```
Entity.where(字段 = 值) : List<Entity>
```

- 语义：按实体某字段等值筛选，返回该实体列表。
- parser：识别 `Ident(Entity).where(...)` 形态（普通 Call/Member，不新增节点）。
- typecheck：`Entity` 必须是已声明实体，`字段` 必须是该实体的属性，`值` 须可赋给字段类型。
- codegen-java：为每个 where 字段生成 JPA 派生查询 `findBy<Field>(<Type> field)`，`Entity.where(...)` → `repo.findByField(val)`。
- codegen-react：透传（where 用于后端逻辑，前端不直接调用）。

### 4.4 ForEach 容器放宽（typecheck）

现有约束：`ForEach 容器必须是已声明实体的 .all 静态引用`（`docs/dev/12` 的检查）。
本切面**放宽**为：容器可以是 `Entity.all` **或** `Entity.where(...)`。
（`for (it in OrderItem.where(orderId = id))` 必须能通过 typecheck。）

### 4.5 事务注解（codegen-java）

logic 若含**写操作**（`.save()` / `.delete()` 语句），生成的 Service 方法自动加 `@Transactional`：

```java
import org.springframework.transaction.annotation.Transactional;

@Transactional
public Order createOrder(OrderInput input) { ... }
```

- 检测：`collectUsedEntities` 或单独扫描 body 中是否有 save/delete 调用语句。
- 保证"插主 + 插明细 + 回写汇总"原子性。

## 5. IR 变更（core）

**不新增节点类型**。全部复用现有 `Expr`/`Statement`：

- 运算符：`Binary.operator` 联合扩为 `'+' | '-' | '*' | '/' | '===' | '!==' | '<' | '<=' | '>' | '>=' | '&&' | '||'`。
- `Entity.where(...)` / `list.add(...)` / `list.count`：普通 `Call`/`Member`，语义在 typecheck/codegen 识别。
- 无新 `AnyNode` 成员，判别联合 `never` 穷尽影响面最小。

## 7. 难点：Decimal 算术

`Decimal` → `java.math.BigDecimal`。Java 的 `BigDecimal` **不能用 `+`/`*` 运算符**，必须用方法：

| TDSL | Java |
|------|------|
| `a + b`（两者 Decimal） | `a.add(b)` |
| `a * b`（Decimal × Integer/Decimal） | `a.multiply(BigDecimal.valueOf(b))` |
| `order.total = 0` | `order.setTotal(BigDecimal.ZERO)` |

- genExpr 需要**类型感知**：`Binary('+')` 时若两侧是 Decimal → 生成 `.add()`；`Binary('*')` → `.multiply()`。
- 需要 track 变量的类型（沿用 `vars: Map<string, string>`，已有机制）。
- 乘法的 `Integer`（qty）需转 `BigDecimal.valueOf(qty)`。

这是本切面**最核心的 codegen 逻辑**，必须处理，否则订单汇总算不出来。
