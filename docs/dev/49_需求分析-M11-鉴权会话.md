# 49 · 需求分析 — 鉴权与会话（登录/注册 + token + 后端鉴权）

> 状态：⏸ 待用户 Gate 确认（阶段一·需求分析）
> 日期：2026-09-20
> 关联：dev/16（M4 View 声明层）、dev/24（M10 运行回路）、dev/46-48（门户/外壳）、dev/35（LLM 优先清单）、dev/14（NASL 对标：SDK/权限裁剪）

## 1. 背景

用户诉求（原话）：**"加个简单的登录和注册，界面上体现企业风格，登录后右上角显示当前登录人和退出按钮。登录后有个 token，所有 api 请求都要带这个 token，后台要鉴权。"**

实测现状（当前代码）：

| # | 现象 | 证据 |
|---|------|------|
| 1 | 全链路**没有任何鉴权概念**：grep `token/login/auth/password` 在 `packages/*/src` 业务代码零命中 | — |
| 2 | 后端不生成任何安全横切层（Filter/Interceptor/WebMvcConfigurer） | `packages/codegen-java/src/*.ts` 零命中；生成物仅 controller/entity/repository/service/structure/support/enums |
| 3 | 前端 `fetch` **不带任何认证头** | `packages/codegen-react/src/index.ts:569`（GET）/`:590`（POST）只带 `Content-Type` |
| 4 | 外壳顶栏写死（应用名 + 模块导航），**无当前用户/退出** | `packages/codegen-react/src/index.ts:3014-3024` |
| 5 | 所有 `page` 都塞进 Layout 且进左侧菜单，**无「免登录 / 不出现在菜单」概念** | `routerFile`：`app.views` 全量进 `MODULES`/`PAGE_MODULE`（`:2941-2962`） |
| 6 | `useMutation` 成功后只 refetch + toast，**无「成功后跳转」** | `hooksFile`（`:615+`）；`navigate` 仅作为按钮动作 |
| 7 | `input` 无 `type` 概念，**密码框会明文显示** | `genInput`（`:1654`）+ `ANTD_OF.input='Input'` |
| 8 | yudao 用户表 `SystemUser` **无 `password` 字段、username 无唯一约束** | `examples/yudao/tdsl/00-model.tdsl:81-85`、`:782` |

结论：**不是"缺一个登录组件"，而是缺一条贯穿 core/parser/typecheck + 双端 codegen 的「鉴权/会话」子系统。**

## 2. 目标（本切面范围）

### F1 鉴权声明（TDSL 书写面）

新增最小声明面，遵循项目「显式声明、编译器零推断」原则：

```tdsl
@auth(user: 'SystemUser', username: 'username', password: 'password')   // 顶层：指明用户实体与字段
```

```tdsl
@public                       // 页面/弹窗级：免登录可访问 + 不进主布局与菜单
@title('登录')
page Login {
  <form submit={useMutation('login')}>
    <input field="username" label="用户名" />
    <input field="password" label="密码" type="password" />
    <button text="登录" />
  </form>
}
```

- `@auth(...)` 显式指名用户实体 + 登录字段名（不猜 `User`/`username`）；
- `@public` 标记公开页（登录/注册），生成端将其渲染为**布局外的全屏页**且不进菜单；
- 未标 `@public` 的页面一律「需登录」；
- 注册/登录业务逻辑仍是普通 `function`（查重、建号、校验、签发），接口仍是普通 `interface`。

### F2 token 签发与后端鉴权

- **不透明 token + DB 表**：登录成功签发随机 token，入库（token / 关联用户 / 过期时间）；后端每个受保护请求校验，未带/无效/过期 → **401**；
- 放行名单：`/healthz`、登录/注册端点（其余全鉴权）；
- 密码**不明文入库**（加盐哈希，算法在设计阶段定，优先零新依赖）；
- 令牌表与拦截器由**生成器产出框架代码**（同 `HealthController` 定位），不写成业务 entity；
- 401 响应体统一（前端据此跳登录）。

### F3 前端会话与守卫

- 登录成功后 token 落地浏览器存储；
- **所有 API 请求自动携带** token（`api.ts` 统一注入，业务页面零感知）；
- **路由守卫**：未登录访问受保护页面 → 跳登录页；已登录访问登录页 → 跳首页；
- 收到 401 → 清 token 并回登录页；
- 退出：清 token 回登录页。

### F4 企业风格外壳 + 顶栏用户区

- 顶栏右侧显示**当前登录人**（昵称）+ 退出按钮（下拉菜单）；
- 登录/注册页走企业风格（品牌区 + 居中卡片）；
- 主布局整体观感保持/增强（不破坏既有页面）。

### F5 yudao 样例改造

- `SystemUser` 补 `password`（及 username 唯一约束）；`@auth` 声明；
- 新增登录/注册页与 `login`/`register` 逻辑 + 鉴权接口；
- 既有全部页面自动变为「需登录」；demo 动线更新（先登录再演示）；
- seed 适配（用户带初始密码）。

## 3. 状态流转（会话）

| 当前态 | 事件 | 目标态 | 说明 |
|--------|------|--------|------|
| 未登录 | 访问受保护页 | 未登录 | 重定向到登录页 |
| 未登录 | 登录成功（凭证正确） | 已登录 | 存 token + 用户信息 → 首页 |
| 未登录 | 登录失败 | 未登录 | 401/业务错误提示，停留 |
| 未登录 | 注册成功 | 未登录 | 可提示后跳登录（或自动登录，设计阶段定） |
| 已登录 | 退出 | 未登录 | 清 token → 登录页 |
| 已登录 | token 过期/被撤销（任意请求 401） | 未登录 | 清 token → 登录页 |
| 已登录 | 访问登录/注册页 | 已登录 | 重定向首页 |

## 4. 权限矩阵

| 端点/资源 | 匿名 | 已登录 | 说明 |
|-----------|------|--------|------|
| `/healthz` | ✅ | ✅ | 运行探针（runner 依赖，必须放行） |
| `/api/auth/register` | ✅ | ✅ | 注册 |
| `/api/auth/login` | ✅ | ✅ | 登录 |
| 其余全部 `/api/**` | ❌ 401 | ✅ | 未带/无效 token 一律 401 |
| 前端页面 | 仅 `@public` 页 | 全部 | 无 `@public` = 需登录 |

> 本轮**不做角色/数据权限**（只区分"登录与否"）；`@role` 语法保留但不由鉴权驱动。

## 5. 非目标（本轮不做）

- 角色/权限矩阵/菜单按角色过滤、数据权限、多租户（dev/39 已裁剪）；
- JWT / OAuth2 / SSO / 刷新令牌 / 记住我 / 验证码 / 找回密码 / 邮件短信；
- 密码策略复杂度校验、登录失败锁定、审计日志、登录日志；
- 前端与后端的 HTTPS/CORS 安全加固（生成工程默认同源代理）；
- 页签级按钮权限（`@auth` 之外的按钮级授权）。

## 6. 验收标准（阶段五依据）

| # | 场景 | 预期 |
|---|------|------|
| A1 | 未登录访问任意业务页 | 自动跳登录页，不泄露数据 |
| A2 | 注册新用户 | 用户入库（密码非明文）；重复用户名被拒并有提示 |
| A3 | 登录成功 | 返回 token；跳首页；顶栏右上显示当前用户昵称 |
| A4 | 登录后调任意业务接口 | 请求头自动带 token，返回 200（无需页面手写） |
| A5 | 直接调受保护接口（不带/伪造 token） | 401 |
| A6 | 点击退出 | 清 token → 登录页；再访问业务页需重新登录 |
| A7 | token 失效后任意请求 | 401 → 自动回登录页 |
| A8 | 密码输入框 | 输入内容以圆点遮蔽（type=password） |
| A9 | 企业风格 | 登录页/顶栏用户区观感统一，无破版 |
| A10 | 无 `@auth` 的应用（jxc/todo） | 生成结果与既有行为**逐字节不变**（无鉴权代码注入） |
| R1 | 回归 | 全仓单测绿、`check-spec` 100%、yudao 双端 build ✓ |

## 7. 受影响面

| 包 | 改动 |
|----|------|
| core | `AppNode.auth?`（侧车字段，避全仓 switch）；`ViewNode` 公开标记（复用 annotations）；token 随机数如需内核则加 |
| parser | 顶层 `@auth(user/username/password)` 解析；页面 `@public` 注解捕获；`input type="password"` 属性 |
| typecheck | `@auth` 指向实体/字段存在性与类型校验（用户名/密码须 String）；`@public` 页面无冲突；缺 `@auth` 则不得使用登录页 |
| codegen-java | 令牌表 + 拦截器（401）+ 放行名单 + 密码哈希工具 + 登录/注册端点接线；**无 `@auth` 时不生成任何鉴权代码** |
| codegen-react | `api.ts` 注入 Authorization；token 存取；路由守卫与 Layout 外公开页；顶栏用户区 + 退出；401 跳登录；登录/注册页样式 |
| examples/yudao | `SystemUser.password` + `@auth` + `@public` 登录/注册页 + login/register 逻辑与端点 + seed 初始密码 + README 动线 |
| docs | 语法手册新增「鉴权与会话」章节；cheatsheet 增补；index.html 同步 |

## 8. 风险

| 风险 | 应对 |
|------|------|
| 鉴权代码污染所有应用（jxc/todo 被迫登录） | **无 `@auth` 时生成结果零变化**（A10 锁死），鉴权只在声明的应用生效 |
| mock token 被当成真安全（错觉） | 文档明确「演示级最小鉴权」；密码加盐哈希；不做越权数据隔离 |
| 生成物 fetch 注入点分散（api.ts 之外还有内联 fetch） | 设计阶段统一收口到 `api.ts` + 一个请求封装；补测试锁死 |
| runner/eval 直接打 yudao 接口（无 token）会被 401 | 运行回路与 seed 需带 token（登录后调用），或提供测试放行策略（设计阶段定） |
| 密码哈希引入新依赖 | 优先 JDK `MessageDigest`（SHA-256 + salt）零新依赖；BCrypt 需依赖则列为待定 |
| 登录页在布局外的路由守卫实现动摇既有 routerFile | 无 `@auth` 应用走原分支，生成逐字节不变；有 `@auth` 才切新分支 |

## 9. 外部依赖

- **不引入**新的 java/npm 运行时依赖（token 随机数用 `java.util.UUID`，哈希用 JDK `MessageDigest`）；
- 沿用既有 `react-router-dom`（守卫用 `<Navigate>`）、`antd`（表单/下拉/消息）。
