## 1. 总体结论（改动面分布）

| 层 | 改动 | 说明 |
|----|------|------|
| parser | **零改动** | `visible={expr}` / `disabled={expr}` 已由通用属性解析落进 `props`（非 Call 不产生 Binding）；`<summary>`、`<detail>` 内 `<repeat>` 同属通用元素解析 |
| core | 零改动（不新增节点/字段） | 复用 `ViewElementNode.props: Record<string, Expr \| string>` 承载条件与求和声明 |
| typecheck | 小改 | KNOWN_VIEW_TYPES 加 `summary`；视图条件表达式**宽松校验**（字段可解则校验存在性，不可解放行——沿 dev/35 策略） |
| codegen-react | **主战场** | 条件渲染/禁用、枚举成员→字符串字面量、detail 只读子表、summary 归约、import 收集同步 |
| codegen-java | 零改动 | F3 全是 logic；库存/核销/回写用既有实体方法与 `@Transactional` |
| examples/yudao | 中等 | 按钮加条件、2 个单据的详情聚合结构体 + 子表、F3 联动 logic、seed 补边界数据 |

设计原则：**不新增语法节点**（判别联合零扩张），把能力挂在既有元素属性上——与 dev/41「@ref 走侧车字段避全仓 switch 爆炸」同一思路。

## 2. 语言面设计

### 2.1 动作可用性（F1）

```tdsl
<button text="审批"   action={useMutation('auditErpPurchaseIn', row.id)}
        visible={row.status === DocStatus.UNAUDIT} />
<button text="编辑"   action={openDialog('erpPurchaseInForm', row)}
        disabled={row.status === DocStatus.AUDITED} />
```

- `visible` / `disabled` 是**通用属性**：任何 `<button>`（列表行内 / 详情抽屉 / 页面级）都可挂；
- 条件表达式**受限子集**（面向书写者与 LLM 都简单）：
  `row.<字段>` 的比较（`===` / `!==` / `>` / `<` / `>=` / `<=`）+ 枚举成员（`EnumType.MEMBER`）+ `&&` / `||` / `!`；
- 不开放函数调用/赋值（保持"纯呈现条件"语义）。

### 2.2 明细合计（F2a）

```tdsl
<repeat field="items"> ... </repeat>
<summary field="items" expr={count * productPrice} label="明细金额合计" />
<summary field="items" of="count" label="总数量" />
```

- 仅 `form` 内有效；`field` 指向同表单的 `repeat`；
- `of="字段"`（单字段求和）与 `expr={表达式}`（按明细行上下文求值）二选一，`expr` 优先；
- 渲染：明细表下方右对齐文本 `{label}：{数值}`，随 state 变化实时刷新。

### 2.3 详情子表（F2b）

```tdsl
<detail dataSource={useQuery('getErpPurchaseInDetail', initial.id)}>
  <text field="in.no" title="入库单号" />
  ...
  <repeat field="items">
    <column field="productId" title="产品" />
    <column field="count" title="数量" />
    <column field="productPrice" title="单价" />
  </repeat>
</detail>
```

- `<detail>` 内 `<repeat>` → **只读明细表**（antd Table，无操作列）；
- 数据来源 = 详情查询返回的聚合结构体字段（`data?.items`）；行类型 = 结构体 `List<XxxItem>` 的实参；
- 列渲染复用既有三态：枚举 → Tag、`@ref`/推断外键 → 显示名、其余原值（复用 `genTable` 的列定义逻辑，抽公共函数）。

## 3. 编译流程（codegen-react）

```
ViewElement.props
  ├─ visible  (Expr) ──► viewExprToJs(row 上下文) ──► { cond && (<Button .../>) }
  ├─ disabled (Expr) ──► viewExprToJs(row 上下文) ──► <Button disabled={cond} .../>
  ├─ <summary>       ──► <div>合计：{ items.reduce((s, it) => s + (expr), 0) }</div>
  └─ <detail><repeat> ──► <Table dataSource={data?.items ?? []} columns={[...]}/>
```

关键点：

1. **枚举成员字面量化**：`DocStatus.UNAUDIT` → `'UNAUDIT'`（实体列存储已是枚举名，前端取值即名字符串）。落在 `exprToJs` 的 `Member` 分支：对象是枚举名 → 输出字符串字面量（对 derive 同样受益）。
2. **条件渲染的折叠兼容**：`foldRowButtonPlan` 仍按**静态按钮数**计算（visible 只影响渲染，不改变「更多」折叠结构），避免操作列宽度抖动。
3. **import 同步**：条件渲染不新增 antd 组件；`summary` 用原生 `div`（零 import 增量）；detail 子表需要 `Table`（复用既有收集路径）。
4. **无属性即原行为**：未写 `visible/disabled/summary` 的页面**生成结果逐字节不变**（兼容 jxc/todo/todo-multi）。

## 4. 业务链设计（F3，纯 logic）

### 4.1 统一库存入口（新增辅助 logic，yudao）

```tdsl
function applyStock(productId: Integer, warehouseId: Integer, delta: Decimal,
                    bizType: StockRecordBizType, bizId: Integer, bizNo: String): Void {
  const s = Stock.where(productId = productId, warehouseId = warehouseId);   // 取现有库存行
  // 无行则建行；有行则累加；写 StockRecord 流水（含 totalCount 快照）
}
```

- 出库前校验 `stock.count >= delta`，不足 `throw '库存不足：<产品> 当前 <n>，需要 <m>'`；
- 反审批用 `delta` 取负 + 反向 bizType（`*_CANCEL`）。

### 4.2 单据联动表

| 动作 logic | 联动（同一 @Transactional） |
|------------|------------------------------|
| `auditErpPurchaseIn` | 逐明细 `applyStock(+count)`；`PurchaseInItem` 无需回写（自身）；回写来源订单明细 `inCount += count`；订单全部满足 → `status=AUDITED` |
| `deauditErpPurchaseIn` | 逐明细 `applyStock(-count)`；订单 `inCount -= count`；订单回 `UNAUDIT` |
| `auditErpPurchaseReturn` | `applyStock(-count)`（退货出库流水） |
| `auditErpSaleOut` | 逐明细库存校验后 `applyStock(-count)`；回写订单明细 `outCount += count`；订单全部满足 → `AUDITED` |
| `deauditErpSaleOut` | `applyStock(+count)`；`outCount -= count` |
| `auditErpSaleReturn` | `applyStock(+count)`（退货入库流水） |
| `auditErpPurchasePayment` | 核销：回写 `PurchaseIn.paymentPrice += paymentPrice`（按 `FinancePaymentItem.bizNo → 入库单`）；订单已付同步 |
| `auditErpSaleReceipt` | 核销：回写 `SaleOut.receiptPrice += receiptPrice` |

- 全部同步执行（无异步/消息）；幂等由状态机前置校验保证（仅 UNAUDIT 可审批）；
- 业务错误统一 `throw` 中文文案（前端已有 `message.error` 弹窗链路）。

### 4.3 详情聚合（F2 样例落地范围）

- 新增结构体：`PurchaseInDetail { in: PurchaseIn; items: List<PurchaseInItem>; }`、`SaleOutDetail { out: SaleOut; items: List<SaleOutItem>; }`；
- 新增查询逻辑：`getErpPurchaseInDetail(id)` / `getErpSaleOutDetail(id)`（组装主表 + `where(inId = id)` 明细）；
- **范围决策**：F2 子表机制通用，但样例先落这 2 个单据（F3 联动的核心对象）；其余 12 个详情页保持主表字段，后续机械扩展。

## 5. 影响面与兼容

| 变更 | 兼容性 |
|------|--------|
| 新属性 `visible/disabled` | 旧页面无此属性 → 生成不变 |
| `exprToJs` 枚举成员字面量化 | 旧 derive 表达式未用枚举成员 → 不变；新能力 |
| `<summary>` / detail 内 `<repeat>` | 新元素/新嵌套，旧样例不涉及 |
| `check-spec` | **不新增维度**（理由：可用性是渲染行为，非要求覆盖项；目标系统的按钮在 spec 里已登记，可用性由单测 + 真机验收）；仅 `summary` 进 KNOWN_VIEW_TYPES |

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| `visible` 让操作列在状态切换时布局跳动 | 主用 `disabled`（保留占位）；`visible` 仅用于互斥动作（审批↔反审批） |
| 枚举成员写在页面上但类型未知 | codegen 仅在「对象名命中枚举表」时字面量化，否则原样输出（typecheck 宽松） |
| 库存联动与 seed 既有数据冲突（重复灌数） | seed 调整：单据审批后由联动生成库存流水，去掉手工库存步骤的重复项 |
| 详情聚合结构体只落 2 个单据被指范围不足 | 设计已注明机制通用 + 扩展清单，Gate 时可要求扩大 |
| `@Transactional` 与自定义 throw 的回滚语义 | 沿用既有 `@Transactional`（运行时异常回滚），文案错误在事务内抛出即回滚 |
